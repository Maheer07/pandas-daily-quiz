## Q1. What does the following print?

```python
import numpy as np
arr = np.array([10, 20, 30, 40, 50])
result = np.where(arr > 25, arr, 0)
print(result)
```
A. [0 0 30 40 50]
B. [10 20 30 40 50]
C. [False False True True True]
D. Raises a ValueError because arr and 0 have different shapes

## Q2. Building on Day 4's `arr2d`, what does this print?

```python
import numpy as np
arr2d = np.array([[1, 2, 3], [4, 5, 6]])
mask = (arr2d > 2) & (arr2d < 6)
print(arr2d[mask])
```
A. [1 2 6]
B. [3 4 5]
C. [[False False  True] [ True  True False]]
D. Raises a TypeError, since `&` cannot be used to combine boolean arrays elementwise

## Q3. Building on Day 4/5's row-wise `keepdims` pattern, what does this print?

```python
import numpy as np
arr2d = np.array([[2, 4, 6], [1, 5, 9]])
threshold = arr2d.max(axis=1, keepdims=True) / 2
print(np.where(arr2d >= threshold, arr2d, -1))
```
A. [[2 4 6] [1 5 9]]
B. [[-1 -1 6] [-1 -1 9]]
C. Raises a ValueError, since threshold has shape (2, 1) and arr2d has shape (2, 3)
D. [[-1 4 6] [-1 5 9]]

## Q4. Given `arr = np.array([45, 72, 88, 30, 95])`, which line correctly caps every value greater than 90 down to 90, leaving the other values unchanged?

A. `np.where(arr > 90, 90)`
B. `arr.where(arr > 90, 90)`
C. `arr[arr > 90] = 90`
D. `np.where(arr > 90) = 90`

## Q5. What does the following print?

```python
import numpy as np
arr2d = np.array([[1, -2, 3], [-4, 5, -6]])
print(np.where(arr2d < 0, 0, arr2d).sum(axis=1))
```
A. [2 -5]
B. [1 5 3]
C. Raises a ValueError due to shape mismatch between arr2d and the scalars
D. [4 5]

## Answer key

1. **A** — `arr > 25` gives `[F,F,T,T,T]`; `np.where(cond, arr, 0)` keeps the original value where the condition is `True` and substitutes `0` elsewhere, giving `[0, 0, 30, 40, 50]`. B wrongly assumes `np.where` here just returns `arr` unchanged. C confuses the three-argument `np.where` (which returns *values*) with the boolean condition array itself. D wrongly assumes the scalar `0` needs to match `arr`'s shape — scalars always broadcast fine against any shape.
2. **B** — Elementwise `&` combines the two boolean masks: `(arr2d > 2)` is `[[F,F,T],[T,T,T]]` and `(arr2d < 6)` is `[[T,T,T],[T,T,F]]`; ANDing them gives `[[F,F,T],[T,T,F]]`. Indexing `arr2d` with that mask pulls the `True` positions in row-major order: `3, 4, 5`. A is what you'd get from the *inverted* mask (values outside the 2–6 range). C is the boolean mask itself, not `arr2d[mask]` — a common mix-up between the condition and the filtered values. D is false: `&` (unlike the plain `and` keyword) is exactly the correct elementwise operator for combining boolean arrays, as long as each condition is parenthesized, which it is here.
3. **D** — `arr2d.max(axis=1, keepdims=True)` gives shape `(2,1)`: `[[6],[9]]`; dividing by 2 gives thresholds `[[3.],[4.5]]`, which broadcast against each row (shape `(2,3)`) since a size-`1` axis always stretches to match. Row 0: `[2,4,6] >= 3` → `[F,T,T]` → `[-1,4,6]`. Row 1: `[1,5,9] >= 4.5` → `[F,T,T]` → `[-1,5,9]`. A wrongly assumes `np.where` here has no effect and returns `arr2d` unchanged. B is what you'd get if you forgot the `/ 2` and compared against the raw row max instead of half of it. C is wrong — a `(2,1)` array broadcasts against a `(2,3)` array without error, the same rule Day 4 Q3 relied on.
4. **C** — Boolean-mask assignment (`arr[arr > 90] = 90`) replaces only the values greater than 90 in place, leaving the rest untouched — the standard, correct pattern. A raises a `ValueError`, because `np.where` requires either exactly one argument (condition only, to get indices) or all three (condition, x, y) — passing just two is invalid. B raises an `AttributeError`: `.where()` is a pandas `Series`/`DataFrame` method, not a NumPy `ndarray` method — a classic pandas/NumPy naming confusion. D is a `SyntaxError`: `np.where(...)` returns a value, and you can't assign to a function call on the left-hand side of `=`.
5. **D** — `np.where(arr2d < 0, 0, arr2d)` replaces every negative entry with `0`, giving `[[1, 0, 3], [0, 5, 0]]`; `.sum(axis=1)` then sums across each row: `1+0+3=4` and `0+5+0=5`, giving `[4, 5]`. A is the sum of the *original* array without replacing negatives first (`1-2+3=2`, `-4+5-6=-5`) — skipping the `np.where` step entirely. B is the `axis=0` result on the cleaned array (column sums `1+0=1`, `0+5=5`, `3+0=3`), the recurring axis mix-up. C is false — scalars like `0` always broadcast against any array shape in `np.where`, so no error occurs.
