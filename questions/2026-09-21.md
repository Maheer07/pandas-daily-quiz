## Q2. Using the same `df`, what happens here?

```python
print(df[df['age'] > 30 & df['score'] > 60])
```
A. Raises a `ValueError` ("The truth value of a Series is ambiguous...") — `&` binds tighter than `>`, so this is parsed as the chained comparison `df['age'] > (30 & df['score']) > 60`, which needs an implicit `and` between two multi-element Series
B. Prints only Dave's row (`age > 30` and `score > 60`), as if the parentheses needed for correct precedence were already implied
C. Raises a `TypeError` because `&` can't be applied between the integer `30` and the Series `df['score']`
D. Prints an empty DataFrame, because no row in `df` satisfies both conditions

## Q3. Still using the same `df`, what does this print?

```python
print(df[(df['age'] < 28) | (df['score'] > 90)])
```
A.
```
      name  age  score
100  Alice   25     88
102  Carol   35     92
```
B.
```
      name  age  score
100  Alice   25     88
```
C. All four rows, since `|` is read as "match everything from either condition, plus everything else"
D. Raises a `ValueError` because `|` requires both sides of the expression to compare the same column

## Q4. Building directly on Day 9's `.loc` column-selection syntax, what does this print?

```python
print(df.loc[df['score'] > 60, 'name'].tolist())
```
A. `['Alice', 'Carol']`
B. `['Alice', 'Carol', 'Dave']`
C. Raises an error, because the row selector and column name are in the wrong order — it should be `df.loc['name', df['score'] > 60]`
D. Raises a `KeyError`, because `.loc` can't take a boolean Series as its row selector — only `.iloc` can

## Q5. Given `cond1 = df['age'] > 30` and `cond2 = df['score'] < 90`, which line raises an error?

A. `df[cond1 & cond2]`
B. `df[cond1 | cond2]`
C. `df[cond1 and cond2]`
D. `df[~cond1]`

## Answer key

1. **A** — `df[boolean_series]` keeps only the rows where the boolean Series is `True`. `df['age'] > 30` is `[F, F, T, T]` for ages `[25, 30, 35, 40]`, so only Carol (35) and Dave (40) survive — a **strict** `>`, so age-30 Bob is excluded. B wrongly includes Bob, treating `>` as `>=`. C is the common misconception that `df[mask]` prints the mask itself rather than using it to filter rows — that's what `df['age'] > 30` alone would print, but wrapping it in `df[...]` performs the actual filtering. D is wrong — passing a boolean Series inside `df[...]` is exactly the standard, valid way to filter a DataFrame.
2. **A** — This is the classic pandas boolean-filtering gotcha: Python's `&` operator has **higher precedence** than `>`, so `df['age'] > 30 & df['score'] > 60` isn't grouped as two separate comparisons — it's parsed as the chained comparison `df['age'] > (30 & df['score']) > 60`, which Python evaluates as `(df['age'] > (30 & df['score'])) and ((30 & df['score']) > 60)`. That implicit `and` tries to coerce a multi-element Series to a single `True`/`False`, which pandas refuses with `ValueError: The truth value of a Series is ambiguous...`. B is what you'd get only *with* explicit parentheses around each comparison (`(df['age'] > 30) & (df['score'] > 60)`) — the fix, not the actual buggy behavior. C misattributes the error: `30 & df['score']` itself is perfectly legal (bitwise AND between an int and an int Series) and doesn't raise; the error comes from the *chained comparison* built around it, not from that inner `&`. D wrongly assumes the code runs to completion and just finds no matches, when in fact it never reaches the point of comparing rows.
3. **A** — Each condition is independently parenthesized, so `|` correctly combines two proper boolean Series row-by-row: `df['age'] < 28` is `[T, F, F, F]` (only Alice), `df['score'] > 90` is `[F, F, T, F]` (only Carol), and `|` keeps a row if *either* is `True` — Alice and Carol. B only applies the first condition, as if `|` were ignored entirely. C is wrong — `|` is a plain logical OR over the two masks, not some blanket "everything" operator. D is wrong — `|` (like `&`) works perfectly well combining boolean masks derived from *different* columns; there's no same-column requirement.
4. **A** — `.loc[row_selector, column_selector]` accepts a boolean Series as the row selector and a column label as the column selector, exactly like Day 9's `.loc[label, column]` pattern but with a mask instead of a single label. `df['score'] > 60` is `[T, F, T, F]`, keeping Alice (88) and Carol (92) but excluding Dave, whose score is exactly `60` (not `> 60`) — giving `['Alice', 'Carol']`. B wrongly includes Dave by treating `> 60` as `>= 60`. C is wrong — the order in the original code (row selector, then column) is correct `.loc` usage; swapping them, as C suggests "fixing" it to, is what would actually raise an `IndexingError` about an unalignable boolean Series. D is wrong — `.loc` fully supports boolean Series as a row selector; this is a normal, documented usage, not something restricted to `.iloc`.
5. **C** — `cond1 and cond2` uses Python's built-in keyword `and`, which tries to evaluate each multi-element Series as a single `True`/`False` value — pandas raises `ValueError: The truth value of a Series is ambiguous...` because it has no way to collapse several boolean values into one. A and B are both fine: `&` and `|` are pandas' element-wise bitwise operators, purpose-built to combine two boolean Series row-by-row without needing a single truth value. D is also fine: `~` is the element-wise negation operator and flips each row's boolean value individually, exactly like `&`/`|` — no ambiguous truth-value evaluation involved.
