## Q1. Building on Day 18's `concat` pattern, Grace simulates a payroll double-sync by appending two of `df6`'s rows back onto itself. What does this print? (Roadmap #31, #15)

```python
import pandas as pd

data6 = {'name': ['Alice', 'Bob', 'Carol', 'Dave', 'Eve', 'Frank'],
         'team': ['Red', 'Blue', 'Red', 'Blue', 'Red', 'Blue'],
         'region': ['North', 'South', 'North', 'North', 'South', 'South'],
         'score': [88, 45, 92, 60, 75, 50]}
df6 = pd.DataFrame(data6, index=[100, 101, 102, 103, 104, 105])

dupes = pd.concat([df6, df6.loc[[100, 102]]], ignore_index=True)
print(dupes.duplicated().tolist())
```
A. `[True, False, True, False, False, False, False, False]` — flips which occurrence counts as "the duplicate," flagging the two *original* rows (Alice at 0, Carol at 2) instead of the later repeats appended at the end
B. `[False, False, False, False, False, False, True, True]` — `duplicated()`'s default `keep='first'` compares every column across all 8 rows; the appended copies of Alice (row 6) and Carol (row 7) exactly match rows 0 and 2 that came before them, so only those two later rows are flagged `True`
C. `[False, False, False, False, False, False, False, False]` — wrongly assumes `duplicated()` compares the DataFrame's *index* rather than its row values, and since `ignore_index=True` gave every row a unique position label 0–7, concludes nothing is duplicated
D. Raises a `TypeError`, assuming `duplicated()` requires an explicit column/subset argument and can't be called with no arguments at all

## Q2. Grace checks two other `keep` settings on the same `dupes` frame to understand the difference. What does this print? (Roadmap #31)

```python
print(dupes.duplicated(keep=False).sum())
print(dupes.duplicated(keep='last').tolist())
```
A. `2` then `[False, False, False, False, False, False, True, True]` — treats `keep=False` as if it behaved like the default `keep='first'` (counting only the 2 "extra" rows), and also treats `keep='last'` as identical to `keep='first'`, missing that the two settings flag opposite ends of each duplicate group
B. `0` then raises `ValueError` — misreads `keep=False` as "turn off duplicate-checking entirely" rather than "flag every row in a duplicate set, with none exempted," and wrongly assumes `'last'` isn't a valid `keep` value
C. `4` then `[False, False, False, False, False, False, True, True]` — correctly counts all 4 rows that participate in a duplicate pair (`keep=False` exempts nothing), but then still applies `keep='first'` logic to the second line instead of flipping which occurrence survives
D. `4` then `[True, False, True, False, False, False, False, False]` — `keep=False` flags every row belonging to a duplicate group (both Alice rows, both Carol rows: 4 total), while `keep='last'` flags every occurrence *except* the last one in each group, so the earlier copies (row 0, row 2) are `True` and their later duplicates (row 6, row 7) are the ones left `False`

## Q3. Contrasting with Day 36's composite-key merge validation, Grace treats `team` + `region` together as a composite key and checks for repeats using `subset`. What does this print? (Roadmap #31, #29)

```python
print(dupes.duplicated(subset=['team', 'region']).tolist())
```
A. `[False, False, True, False, False, True, True, True]` — with `subset`, pandas only compares the named columns, ignoring `name`/`score`; Carol (row 2) repeats Alice's `(Red, North)` pair from row 0, Frank (row 5) repeats Bob's `(Blue, South)` pair from row 1, and both appended rows (6, 7) repeat `(Red, North)` again — four total repeats, even though several of those rows have different names and scores
B. `[False, False, False, False, False, False, True, True]` — wrongly assumes `subset` only flags rows that are *also* exact full-row duplicates (same as Q1's result), missing that Bob/Frank and Alice/Carol already share a `team`+`region` pair despite having different names and scores
C. Raises a `TypeError`, wrongly assuming `subset` must be a single column name string rather than a list of several column names
D. `[False, False, True, False, False, True, False, False]` — correctly spots the Alice/Carol and Bob/Frank repeats but wrongly assumes rows 6 and 7 don't count toward subset duplication since they were "already" duplicates from Q1's full-row check, double-counting the same pair instead of flagging each of the 4 later matches independently

## Q4. Grace wants to keep just the most-recently-logged row per `team`+`region` combo, in original row order, and drop the rest. What does this print? (Roadmap #31, #26)

```python
cleaned = dupes.drop_duplicates(subset=['team', 'region'], keep='last')
print(cleaned['name'].tolist())
```
A. `['Alice', 'Bob', 'Dave', 'Eve']` — uses `keep='first'` logic instead of the `keep='last'` that was actually requested, keeping each group's earliest row rather than its latest
B. Raises a `TypeError`, wrongly assuming `subset` must be a plain string column name rather than a list of multiple columns
C. `['Dave', 'Eve', 'Frank', 'Carol']` — `keep='last'` keeps the last row of each `(team, region)` group: `(Blue, North)`→row 3 Dave, `(Red, South)`→row 4 Eve, `(Blue, South)`→row 5 Frank, `(Red, North)`→row 7 (the appended Carol copy); `drop_duplicates` preserves each survivor's original row position, so by position (3, 4, 5, 7) the names print in that order
D. `['Carol', 'Dave', 'Eve', 'Frank']` — gets the same 4 correct survivors but wrongly assumes `drop_duplicates` reorders the result (e.g. by first-appearance of each group) rather than preserving each kept row's own original position in `dupes`

## Q5. Building on Day 34's `~` boolean-mask pattern, Grace wants only the names with no duplicate anywhere in `dupes` — not even one surviving copy. What does this print? (Roadmap #31, #28)

```python
truly_unique = dupes[~dupes.duplicated(keep=False)]
print(sorted(truly_unique['name'].tolist()))
```
A. `[]` — misreads `keep=False` as "keep nothing at all" rather than as "flag every row involved in any duplicate set, exempting none," so wrongly assumes the whole frame gets filtered away
B. `['Bob', 'Dave', 'Eve', 'Frank']` — `keep=False` flags all 4 rows belonging to a duplicate group (both Alice rows, both Carol rows), so `~` removes every one of them; only Bob, Dave, Eve, and Frank never appear more than once, and alphabetically they already sort in that order
C. `['Alice', 'Bob', 'Carol', 'Dave', 'Eve', 'Frank']` — mentally substitutes the default `keep='first'` behavior for `keep=False`, which would only drop the 2 *appended* rows (6, 7) and leave one surviving copy of Alice and Carol each, missing that `keep=False` exempts no occurrence at all
D. Raises a `TypeError`, wrongly assuming `keep` only accepts the strings `'first'`/`'last'` and rejects the boolean `False`

## Answer key

1. **B** — `duplicated()`'s default `keep='first'` compares all columns across the full 8-row frame; the two rows appended at the end (6: Alice, 7: Carol) exactly match earlier rows (0 and 2), so only those later copies are flagged `True`, giving `[False, False, False, False, False, False, True, True]`. A inverts which occurrence gets flagged — `keep='first'` always leaves the *earliest* occurrence as `False` and marks the rest. C is wrong about what's being compared — `duplicated()` looks at row *values*, never the index, so `ignore_index=True` giving every row a unique position has no bearing on the result. D invents a required argument that doesn't exist; `duplicated()` has a sensible all-columns default.
2. **D** — `keep=False` flags every row that belongs to a duplicate group, exempting none, so all 4 rows (both Alice copies, both Carol copies) come back `True`, giving a sum of 4. `keep='last'` flags every occurrence in a group *except* the last one, so within each pair the earlier row (0 for Alice, 2 for Carol) is `True` and the later, appended copy (6, 7) is the exempted `False`, giving `[True, False, True, False, False, False, False, False]`. A collapses both settings into default `keep='first'` behavior, undercounting the sum and flagging the wrong occurrence in the second line. B misreads `False` as disabling the check entirely rather than as "flag all duplicates," and wrongly assumes `'last'` is an invalid value when it's one of `keep`'s three documented options. C gets the `keep=False` sum right but still applies `keep='first'` logic on the second line instead of flipping which occurrence is exempted.
3. **A** — `subset=['team', 'region']` ignores `name` and `score` entirely, so any rows sharing the same team-and-region pair count as duplicates regardless of who they are: Carol (row 2) repeats Alice's `(Red, North)`, Frank (row 5) repeats Bob's `(Blue, South)`, and the two appended rows (6, 7) repeat `(Red, North)` yet again, giving `[False, False, True, False, False, True, True, True]`. B only catches the exact full-row duplicates from Q1, missing that `subset` deliberately makes *more* rows count as duplicates by ignoring the differing `name`/`score` values. C is wrong — `subset` accepts a list of column names precisely so composite keys like this can be checked together. D undercounts by assuming the appended rows are somehow already "used up" by Q1's check; each of the 4 later `(Red, North)`/`(Blue, South)` matches is flagged independently of any other column's duplicate status.
4. **C** — Grouping `dupes` by `(team, region)`, `keep='last'` keeps each group's latest row: Dave (row 3) for `(Blue, North)`, Eve (row 4) for `(Red, South)`, Frank (row 5) for `(Blue, South)`, and the appended Carol row (row 7) for `(Red, North)`. `drop_duplicates` never reshuffles survivors — they stay in their original relative row order — so by position (3, 4, 5, 7) the printed order is `['Dave', 'Eve', 'Frank', 'Carol']`. A applies `keep='first'` instead, which would keep each group's earliest row (Alice, Bob, Dave, Eve) rather than its latest. B is wrong about `subset`'s signature — it's designed to take a list of columns for exactly this kind of composite-key check. D reaches the right 4 survivors but invents a reordering step that `drop_duplicates` doesn't perform.
5. **B** — `keep=False` flags both occurrences of every duplicate group (Alice's rows 0 & 6, Carol's rows 2 & 7) as `True`, so `~` drops all 4 of those rows outright, leaving only the names that appear exactly once: Bob, Dave, Eve, Frank — which happen to already be alphabetical. A misreads `False` as a blanket "drop everything" signal rather than as "exempt no occurrence from being flagged," when in fact 4 of the 8 rows survive. C is the bug this question is designed to catch: swapping in the default `keep='first'` behavior only removes the 2 *appended* rows, leaving one surviving copy of Alice and Carol each, so it wrongly keeps all 6 distinct names instead of excluding the two that have any duplicate at all. D is wrong — `keep` explicitly documents `False` as a valid third option alongside `'first'`/`'last'`, not just the two strings.
