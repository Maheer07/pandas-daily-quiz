## Q1. Building on Day 11's name/age/score DataFrame, what does this print?

```python
import pandas as pd

df = pd.DataFrame(data, index=[100, 101, 102, 103])
df2 = df.assign(passed=df['score'] >= 60)

```
A. `(4, 4) (4, 4)`

## Q2. Spot the bug: this code is meant to remove the `score` column but doesn't do what's intended. What actually happens?

```python
import pandas as pd
data = {'name': ['Alice', 'Bob', 'Carol', 'Dave'], 'age': [25, 30, 35, 40], 'score': [88, 45, 92, 60]}
df = pd.DataFrame(data, index=[100, 101, 102, 103])

df = df.drop('score')
print(df.columns.tolist())
```
A. Raises a `TypeError`, because `drop()` needs a list, not a bare string
B. Raises a `KeyError`, because default `axis=0` means `drop()` looks for a row label `'score'`, not a column; fix with `df.drop('score', axis=1)` or `df.drop(columns='score')`
C. `['name', 'age']` — `drop()` removes columns by default when given a single string
D. `['name', 'age', 'score']`, unchanged — `drop()` without `inplace=True` never modifies anything, even when reassigned back to `df`

## Q3. Building on Day 8's DataFrame construction, what does this print?

```python
import pandas as pd
data = {'name': ['Alice', 'Bob', 'Carol', 'Dave'], 'age': [25, 30, 35, 40], 'score': [88, 45, 92, 60]}
df = pd.DataFrame(data, index=[100, 101, 102, 103])
result = df.insert(1, 'bonus', df['score'] * 0.1)
print(result, df.columns.tolist())
```
A. A copy of `df` with columns `['name', 'bonus', 'age', 'score']` — like `assign`, `insert` returns the modified DataFrame
B. `None` `['name', 'age', 'bonus', 'score']` — position `1` means "after the 2nd existing column"
C. Raises a `ValueError`, because you can't insert a column anywhere except the end
D. `None` `['name', 'bonus', 'age', 'score']` — `insert` mutates `df` in place and always returns `None`, unlike `assign`

## Q4. Building on Day 11's row-filtering DataFrame, what does this print?

```python
import pandas as pd
data = {'name': ['Alice', 'Bob', 'Carol', 'Dave'], 'age': [25, 30, 35, 40], 'score': [88, 45, 92, 60]}
df = pd.DataFrame(data, index=[100, 101, 102, 103])
df.loc[104] = ['Eve', 22, 75]
print(df.shape, df.loc[104, 'name'])
```
A. `(4, 3) 'Eve'` — assigning to a nonexistent label via `.loc` silently fails, since `.loc` can only update existing rows
B. `(5, 3) 'Eve'` — assigning a list to a new `.loc` label appends it as a new row, in place
C. Raises a `KeyError`, because label `104` doesn't exist in `df`'s index yet
D. `(5, 4) 'Eve'` — pandas adds both a new row and a new column to accommodate the extra list item

## Q5. Given this fresh DataFrame, which line raises an error?

```python
import pandas as pd
data = {'name': ['Alice', 'Bob', 'Carol', 'Dave'], 'age': [25, 30, 35, 40], 'score': [88, 45, 92, 60]}
df = pd.DataFrame(data, index=[100, 101, 102, 103])
```
A. `df.drop(columns='score')`
B. `df.drop('age', axis=1)`
C. `df.insert(len(df.columns), 'bonus', 0)`
D. `df.insert('name', 'bonus', 0)`

## Answer key

1. **C** — `.assign()` always returns a **new** DataFrame with the extra column added, leaving the original untouched: `df` stays `(4, 3)` while `df2` gains the `passed` column and becomes `(4, 4)`. A wrongly assumes `assign` mutates `df` in place (it never does — there's no `inplace` option for `assign`). B forgets the new column entirely, as if `assign` had no effect on `df2`. D is wrong — `assign`'s keyword becomes a brand-new column name; it doesn't need to pre-exist.
2. **B** — `drop()`'s default `axis` is `0` (rows), so `df.drop('score')` searches the **row index** `[100, 101, 102, 103]` for a label `'score'`, doesn't find one, and raises `KeyError: "['score'] not found in axis"`. To drop a column you need `axis=1` or the `columns=` keyword. A is wrong — a single string is a perfectly valid `labels` argument to `drop()`; no list is required. C wrongly assumes `drop()` targets columns by default. D is wrong on two counts: `inplace` isn't needed when you reassign the result back to `df` (that's the whole point of the non-`inplace` API) — but it's moot here anyway since the call raises before any column could be dropped.
3. **D** — `insert(loc, column, value)` always mutates the DataFrame **in place** and returns `None` — unlike `assign`, there's no "returns a new object" variant. `loc=1` inserts the new column at *position* 1 (0-indexed), i.e. right after `'name'` (position 0) and before `'age'` (which shifts from position 1 to 2), giving `['name', 'bonus', 'age', 'score']`. A is wrong — confusing `insert`'s in-place/`None`-returning behavior with `assign`'s copy-returning behavior. B miscounts the insertion position, treating `loc=1` as "after the first *two* columns" instead of "at position 1". C is wrong — `insert` happily inserts anywhere from position `0` up to `len(df.columns)` inclusive, not just at the very end.
4. **B** — Assigning a list to `.loc` with a **label that doesn't yet exist** creates a brand-new row at that label, mutating `df` in place — this is the standard idiom for appending a single row. `df.shape` becomes `(5, 3)` and the new row's `'name'` value is `'Eve'`. A is wrong — `.loc` explicitly supports creating new rows this way; it doesn't silently no-op. C is wrong — no error occurs; `.loc[newlabel] = ...` is documented, valid pandas behavior. D is wrong — the list `['Eve', 22, 75]` has exactly 3 elements, matching the 3 existing columns, so it fills the existing columns rather than creating a 4th.
5. **D** — `insert`'s first argument, `loc`, must be an **integer position**, never a column label; passing the string `'name'` raises `TypeError: loc must be int`. A and B are both valid, equivalent ways to drop a column (`columns=` kwarg vs. `axis=1`) and run without error. C is also valid — `insert` accepts `loc` anywhere from `0` up to and including `len(df.columns)`, so inserting at the "one past the end" position is a legal way to append a column, not an out-of-bounds error.
