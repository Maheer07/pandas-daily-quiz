## Q5. What is the shape of the result?

```python
import numpy as np
col = np.array([[1], [2], [3]])
row = np.array([10, 20, 30])
print((col + row).shape)
```
A. (3, 3)
B. (3, 1)
C. (1, 3)
D. Raises a ValueError

## Answer key

1. **A** — Vectorized ops follow standard arithmetic order across the whole array: `arr * 2` gives `[20,40,60,80,100]`, then `- 5` subtracts elementwise, giving `[15,35,55,75,95]`. B forgets the subtraction step entirely. C applies only the subtraction and drops the multiplication. D wrongly assumes chained scalar ops on an array need an explicit cast — no error occurs.
2. **A** — `row` has shape `(3,)` which broadcasts against `arr2d`'s shape `(2,3)` by being added to *every* row: `[1+10,2+20,3+30]=[11,22,33]` and `[4+10,5+20,6+30]=[14,25,36]`. B wrongly adds `row` only to the first row and leaves the second row's original values in place. C incorrectly assumes shapes `(2,3)` and `(3,)` are incompatible — trailing dimensions `3` and `3` match, so this broadcasts fine. D wrongly assumes broadcasting *replaces* each row with `row` instead of adding to the existing values.
3. **A** — `a` has shape `(2,3)` and `b` has shape `(2,)`. Broadcasting aligns shapes from the trailing dimension: `3` vs `2` don't match and neither is `1`, so NumPy raises a `ValueError`. B is what you'd get if `b` were reshaped to `(2,1)` first (a column vector) — a very common mix-up between "broadcast down rows" and "broadcast across columns". C wrongly assumes the operation reduces each row to a single sum. D wrongly assumes NumPy pads the shorter array with a no-op and adds elementwise only where lengths overlap, like `zip` in plain Python — NumPy broadcasting has no such fallback.
4. **A** — Comparison operators are vectorized and always return a boolean array (`dtype=bool`), and boolean-mask indexing (`arr[mask]`) returns the *values* where the mask is `True`: `30, 40, 50`. B wrongly assumes the mask keeps the array's original dtype. C confuses `arr[mask]` (the filtered values) with `mask` itself (the boolean array). D inverts the condition, as if `>` had selected `10, 20` (values that are *not* greater than 25).
5. **A** — `col` has shape `(3,1)` and `row` has shape `(3,)`, which NumPy treats as `(1,3)` for alignment. Comparing `(3,1)` and `(1,3)`, each axis with size `1` stretches to match the other, giving a broadcast result of shape `(3,3)` (every row-element pair summed). B wrongly assumes the row vector has no effect on shape. C wrongly assumes the column vector's shape is discarded in favor of the row's. D confuses this with Q3's case — here one of the mismatched dimensions is exactly `1`, which is the one case broadcasting *does* stretch, so no error is raised.
