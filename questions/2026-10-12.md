## Q1. Building on the recurring `df6` and the groupby mean you've used all week, what does this print? (Roadmap #21)

```python
import pandas as pd
data6 = {'name': ['Alice', 'Bob', 'Carol', 'Dave', 'Eve', 'Frank'],
         'team': ['Red', 'Blue', 'Red', 'Blue', 'Red', 'Blue'],
         'region': ['North', 'South', 'North', 'North', 'South', 'South'],
         'score': [88, 45, 92, 60, 75, 50]}
df6 = pd.DataFrame(data6, index=[100, 101, 102, 103, 104, 105])

s = df6.groupby(['team', 'region'])['score'].mean()
print(s.loc['Blue'])
```
A. A `Series` indexed by `region` alone (`North` 60.0, `South` 47.5) — `.loc` with just the outer-level label collapses that level and keeps the rest
B. Raises a `KeyError`, because `s` has a `MultiIndex`, so `.loc` requires a full tuple key like `('Blue', 'North')`, not a single label
C. The scalar `60.0`, because `.loc['Blue']` is treated as matching only the first row where `team == 'Blue'`
D. A `DataFrame` with columns `region` and `score`, because grouping by two keys always returns 2-D results even after `['score']` selection

## Q2. Building on Q1's `s`, what are the level names of the result, in order (outer to inner)? (Roadmap #21)

```python
s2 = s.swaplevel()
print(s2.index.names)
```
A. `region`, then `team` — `swaplevel()` with no arguments swaps the last two levels, which for a 2-level `MultiIndex` means swapping outer and inner
B. `team`, then `region` — unchanged, because `swaplevel()` needs explicit level positions or names to actually do anything
C. `None`, then `None` — swapping levels also clears their names
D. Raises a `TypeError`, because `swaplevel()` requires explicit `i`/`j` arguments on a 2-level index

```python
df6_idx = df6.set_index(['team', 'region'])
print(df6_idx.loc[('Red', 'North'), 'score'].tolist())
```
A. `[88, 92]` — `set_index()` doesn't collapse or deduplicate anything; both rows matching `('Red', 'North')` (Alice, then Carol, in their original order) stay in the result, and `.loc` with a full tuple key returns all of them as a `Series`
B. Raises a `ValueError: Index contains duplicate entries, cannot reshape` — same failure as `.pivot()` hits on this exact pair, because `.loc` can't resolve a `MultiIndex` key that matches more than one row
C. `[90.0]` — a single averaged value, because `.loc` with a complete tuple key implicitly aggregates duplicate matches the way `pivot_table` does
D. Raises a `KeyError`, because `.loc` only accepts one level at a time for a `MultiIndex` — a combined tuple like `('Red', 'North')` isn't valid syntax

## Q5. Building on Q1's `s` (a `Series` named `'score'`, with `MultiIndex` levels named `team`/`region`), what does this print? (Roadmap #21)

```python
s3 = s.reset_index()
print(s3.columns.tolist())
```
A. `['team', 'region', 'score']` — `reset_index()` turns each named `MultiIndex` level into its own column (using its existing name), and the Series' values become a column named after the Series itself (`'score'`)
B. `['level_0', 'level_1', 'score']` — `reset_index()` always falls back to generic `level_N` names for `MultiIndex` levels, regardless of whether they already have names
C. `['team', 'region', 0]` — the value column takes the generic default name `0`, since a Series' own `.name` is ignored by `reset_index()`
D. Raises a `TypeError`, because `reset_index()` is a `DataFrame`-only method and isn't defined on a `Series`

## Answer key

1. **A** — `.loc` on a `MultiIndex` supports *partial indexing*: a single label matches against the outermost level and collapses it, returning a `Series` indexed by whatever levels remain (`region` here) — `Blue`/`North` is Dave alone (60.0), `Blue`/`South` is Bob & Frank's mean (47.5). B wrongly assumes a full tuple is mandatory — it's only needed when you want to pin down more than the outer level. C confuses "matches the first row" with what actually happens (a full cross-section, not a single value). D is wrong — grouping by two keys and then selecting `['score']` keeps the result 1-D; it's a `Series` the whole way through, not a `DataFrame`.
2. **A** — with no arguments, `swaplevel()` defaults to swapping the last two levels (`i=-2, j=-1`), which for a 2-level index means outer and inner trade places: `('team', 'region')` becomes `('region', 'team')`. B wrongly assumes the no-argument call is a no-op — it isn't; swapping the only two levels of a 2-level index is exactly what the default does. C invents a side effect — swapping level *order* doesn't erase level *names*, those travel with their level. D is wrong — `i`/`j` both default to `-2`/`-1`, so calling `swaplevel()` bare is valid and does something meaningful on a 2-level index.
3. **A** — `.xs(key, level=...)` is built specifically to pull a cross-section from a named inner level without needing the outer level's labels at all, returning `Blue -> 47.5, Red -> 75.0`. B and C both fail because plain `.loc['South']` / `s['South']` match against the **outer** level first, and `'South'` only exists at the inner (`region`) level — there's no `team` called `'South'`, so both raise `KeyError` for the same reason. D is a distinct bug: swapping `.xs()`'s positional `key` and the `level` keyword makes pandas search for a level *named* `'South'`, which doesn't exist, so it fails before the lookup it was meant to do.
4. **A** — `set_index()` only changes which columns act as the row labels; it performs no deduplication or aggregation, so both of `df6`'s `Red`/`North` rows (Alice=88, Carol=92) survive in their original order. A full tuple key like `('Red', 'North')` is exactly the supported way to query a 2-level `MultiIndex` with `.loc`, and when multiple rows share that key, `.loc` simply returns all of them as a `Series` — no error. B wrongly imports `.pivot()`'s duplicate-key restriction; that's a `.pivot()`-specific limitation (it needs a unique index/column pairing because it performs no aggregation step of its own kind), not a general `.loc` restriction. C invents an implicit-averaging behavior that `.loc` never performs — only `pivot_table`/`groupby` aggregate; plain label lookup never does. D is wrong — a tuple is precisely the correct, standard way to supply a multi-level key to `.loc` in one call.
5. **A** — `reset_index()` promotes each `MultiIndex` level back into an ordinary column, reusing that level's existing name (`team`, `region` here, since the `groupby(['team', 'region'])` call gave them those names) — and the Series' own values become a new column named after the Series itself, `'score'`. B describes what happens only when levels have *no* name at all (then pandas falls back to `level_0`, `level_1`, ...) — not the case here, since groupby already named them. C is wrong for the same reason in reverse: the Series' `.name` attribute (`'score'`) is exactly what `reset_index()` uses for the value column; it's not ignored. D is wrong — `Series.reset_index()` is a real, commonly used method; it is not `DataFrame`-only.
