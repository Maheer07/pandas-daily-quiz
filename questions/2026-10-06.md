## Q1. Building on the recurring `team`-augmented DataFrame, a `joined` column is added and converted. What does this print? (Roadmap #18)

import pandas as pd
data = {'name': ['Alice', 'Bob', 'Carol', 'Dave'],
        'team': ['Red', 'Blue', 'Red', 'Green'],
        'score': [88, 45, 92, 60],
        'joined': ['2023-03-14', '2022-11-01', '2023-03-14', '2021-07-30']}
df = pd.DataFrame(data, index=[100, 101, 102, 103])
df['joined'] = pd.to_datetime(df['joined'])

print(df['joined'].dt.year.tolist())
```

## Q2. Spot the bug: this is meant to pull the join year out of the `name`/`joined` DataFrame, but doesn't do what's intended. What actually happens? (Roadmap #18)

df2 = pd.DataFrame(data)

print(df2['joined'].dt.year)
```

B. Raises an `AttributeError`, because `.dt` only works on a `datetime64`-typed Series, and `joined` here is still string-typed — `pd.to_datetime()` was never called on it
C. Raises a `ValueError`, because the date strings use dashes instead of slashes
D. Prints `NaN` for every row, because pandas can't infer the date format automatically

## Q4. What does this print? (Roadmap #18)

## Q5. Building on Day 20/21's `df6` (`name`, `team`, `region`, `score`), now with a `joined` column of date strings added, which line raises an error? (Roadmap #18)

```python
import pandas as pd
data6 = {'name': ['Alice', 'Bob', 'Carol', 'Dave', 'Eve', 'Frank'],
         'team': ['Red', 'Blue', 'Red', 'Blue', 'Red', 'Blue'],
         'region': ['North', 'South', 'North', 'North', 'South', 'South'],
         'joined': ['2023-01-10', '2023-02-15', '2023-01-10', '2023-03-20', '2023-02-15', '2023-03-20'],
         'score': [88, 45, 92, 60, 75, 50]}
df6 = pd.DataFrame(data6, index=[100, 101, 102, 103, 104, 105])
```
A. `pd.to_datetime(df6['joined']).dt.month`
B. `df6['joined'].dt.month`
C. `df6.set_index(pd.to_datetime(df6['joined'])).resample('ME')['score'].mean()`
D. `df6['score'].astype(float)`

## Answer key

1. **A** — `pd.to_datetime()` converts the string column to real `datetime64` values, and the `.dt` accessor then exposes per-element date parts; `.dt.year` pulls the year out of each timestamp as an integer, giving `[2023, 2022, 2023, 2021]`. B wrongly assumes `.dt.year` returns strings — it returns integers (`int32`), not text. C is backwards — `.dt` requires a *datetime*-typed Series, not a string-typed one; here the column was already converted, so it works fine. D confuses `.dt.year` with `.dt.day` — those are the day-of-month values (14, 1, 14, 30), not the years.
2. **B** — `df2['joined']` is still a plain string column; `pd.to_datetime()` was never applied to it, so it has no `datetime64` dtype. The `.dt` accessor only works on datetime-like data, so calling `.dt.year` raises `AttributeError: Can only use .dt accessor with datetimelike values`. A wrongly assumes pandas auto-converts date-*looking* strings just because they're formatted like dates — it never does this implicitly; conversion is always an explicit step. C is wrong — nothing here calls a date parser at all, so no parsing-format error can occur. D is wrong — there's no silent `NaN`-filling behavior for this; accessing `.dt` on non-datetime data is a hard error, not a quiet failure.
3. **A** — `pd.to_datetime()` defaults to the US-style month-first convention (`dayfirst=False`, the default unless stated otherwise) when parsing `MM/DD/YYYY`-shaped strings, applied independently to each element: `'03/04/2023'` → month `03`, day `04` → March 4, and `'11/01/2023'` → month `11`, day `01` → November 1. B assumes `dayfirst=True` behavior (reading the first number as the day), which only applies if that argument is explicitly passed — it isn't here. C is wrong — pandas does *not* refuse to parse these strings by default; it silently applies its default month-first convention rather than raising. D wrongly keeps the month-first reading for the first string but switches to a day-first reading for the second, when in fact the same convention is applied consistently to every element.
4. **A** — `.resample('3D')` groups the 6 daily-indexed values into non-overlapping 3-day buckets starting from the first timestamp: days 1-3 (`10+20+15=45`) and days 4-6 (`25+30+5=60`), then `.sum()` aggregates each bucket. B wrongly assumes `.resample()` without a terminal aggregation already returns the original values unchanged — `.resample()` only builds the grouping; `.sum()` is what actually aggregates it, and it was called here. C is wrong — `ts` is indexed by `rng`, a `DatetimeIndex` (from `pd.date_range`), not a default integer index, so `.resample()` works fine. D wrongly collapses everything into a single bucket, as if `'3D'` meant "the first 3 days only" rather than repeating 3-day windows across the whole series.
5. **B** — `df6['joined']` is a plain string column (no `pd.to_datetime()` was called on `df6` itself), so `.dt.month` raises `AttributeError: Can only use .dt accessor with datetimelike values`, exactly like Q2. A is valid — wrapping the column in `pd.to_datetime(...)` first produces a real datetime Series, so `.dt.month` works on *that* intermediate result. C is valid — `pd.to_datetime(df6['joined'])` is used to build the index before resampling, and `'ME'` (month-end) is the modern frequency alias for monthly resampling, so this runs cleanly. D is valid — `score` is already numeric (`int64`), and casting it to `float` is unproblematic.
