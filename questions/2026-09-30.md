## Q1. Building on the recurring `team`-augmented DataFrame, now merging in a team-info table, what does this print? (Roadmap #15)

```python
import pandas as pd
data = {'name': ['Alice', 'Bob', 'Carol', 'Dave'],
        'team': ['Red', 'Blue', 'Red', 'Green'],
        'score': [88, 45, 92, 60]}
df = pd.DataFrame(data, index=[100, 101, 102, 103])

team_info = pd.DataFrame({'team': ['Red', 'Blue', 'Yellow'],
                           'manager': ['Grace', 'Heidi', 'Ivan']})

result = df.merge(team_info, on='team', how='left')
print(result[['name', 'team', 'manager']])
```
A.
```
    name   team manager
0  Alice    Red   Grace
1    Bob   Blue   Heidi
2  Carol    Red   Grace
3   Dave  Green     NaN
```
B.
```
    name   team manager
0  Alice    Red   Grace
1    Bob   Blue   Heidi
2  Carol    Red   Grace
```
C.
```
    name   team manager
0  Alice    Red   Grace
1    Bob   Blue   Heidi
2  Carol    Red   Grace
3   Dave  Green     NaN
4    NaN Yellow    Ivan
```
D. Raises a `MergeError`, because both `df` and `team_info` would end up with overlapping `team` columns and no suffixes were provided

## Q2. Spot the bug: this is meant to attach each employee's `manager` by matching on `team`, but doesn't do what's intended. What does it actually print? (Roadmap #15)

```python
import pandas as pd
data = {'name': ['Alice', 'Bob', 'Carol', 'Dave'],
        'team': ['Red', 'Blue', 'Red', 'Green'],
        'score': [88, 45, 92, 60]}
df = pd.DataFrame(data, index=[100, 101, 102, 103])

team_info = pd.DataFrame({'team': ['Red', 'Blue', 'Yellow'],
                           'manager': ['Grace', 'Heidi', 'Ivan']})

result = df.join(team_info, rsuffix='_info')
print(result[['name', 'team', 'manager']])
```

```
C. Raises a `ValueError`, because `team` appears in both `df` and `team_info` and only `rsuffix` was given, not `lsuffix`

## Q3. Given `df` and a second batch of new hires with the same columns, which line correctly stacks them into one 6-row DataFrame? (Roadmap #15)

data = {'name': ['Alice', 'Bob', 'Carol', 'Dave'],
        'team': ['Red', 'Blue', 'Red', 'Green'],
        'score': [88, 45, 92, 60]}
df = pd.DataFrame(data, index=[100, 101, 102, 103])

new_hires = pd.DataFrame({'name': ['Eve', 'Frank'],
                           'team': ['Yellow', 'Red'],
                           'score': [70, 95]}, index=[104, 105])
```
A. `pd.concat([df, new_hires])`
B. `df.merge(new_hires, on='team')`
C. `df.join(new_hires, how='outer')`
D. `pd.concat([df, new_hires], axis=1)`

## Q5. Given `df`, `team_info`, and `new_hires` from Q1/Q3, which line raises an error? (Roadmap #15)

A. `pd.concat([df, new_hires])`
B. `df.merge(team_info, on='manager')`
C. `df.join(team_info.set_index('team'), on='team')`
D. `pd.concat([df, team_info], axis=1)`

## Answer key

1. **A** — `how='left'` keeps every row from `df` (the left frame) and looks up a matching `manager` from `team_info` wherever `team` matches; Alice and Carol (`Red`) get `Grace`, Bob (`Blue`) gets `Heidi`, and Dave (`Green`) has no match in `team_info` so his `manager` is `NaN`. Note the result also gets a fresh `0..3` `RangeIndex` — `merge` doesn't preserve the original index. B is what a (non-default) `how='inner'` merge would give — it silently drops Dave's unmatched row instead of keeping it with `NaN`. C is the `how='outer'` result — it wrongly also pulls in `Yellow` from `team_info` even though no employee is on that team, padding `name`/`score` with `NaN`. D is wrong — the shared key column named in `on=` never gets suffixed or causes a conflict; suffixes only matter for *other* overlapping, non-key columns.
2. **A** — `.join()` combines on the **index** by default, not on a shared column. `df`'s index is `[100, 101, 102, 103]` while `team_info` still has its default `RangeIndex` `[0, 1, 2]` — none of those index values match, so every row's `manager` (and the suffixed `team_info` column) comes back `NaN`, even though every team name does have a real match in `team_info`. B is the result the author *intended* — matching by `team` values — but that's not what index-based `.join()` actually does here. C is wrong — `rsuffix='_info'` is exactly enough to resolve the one overlapping `team` column (it becomes `team_info` on the right side), so no `ValueError` is raised. D misunderstands `rsuffix` — it's a suffix appended to *colliding column names*, not a requirement that a column literally named `team_info` already exist.
3. **A** — `pd.concat([df, new_hires])` defaults to `axis=0`, stacking the rows of both DataFrames on top of each other since they share the same columns, giving one combined 6-row DataFrame. B is wrong — `.merge(..., on='team')` combines columns by matching key *values*, and since `'Red'` appears in both frames it would produce a row-multiplying combination of matching pairs, not a clean row-wise stack. C is wrong — `.join()` aligns on the **index**, and since `df` (index `100-103`) and `new_hires` (index `104-105`) don't overlap, this produces one row per unique index with a jumble of `NaN`-padded, suffix-needing columns (and would in fact raise `ValueError` here since both have unsuffixed overlapping `name`/`team`/`score` columns) — not a row-wise stack either way. D is wrong — `axis=1` glues DataFrames **side by side** by index instead of stacking rows, which (again, given non-overlapping indices) produces a wide, mostly-`NaN` 6-row-by-6-column mess rather than 6 rows of the original 3 columns.
4. **A** — With `how='outer'` and `indicator=True`, pandas adds a `_merge` column showing where each row's key came from. `'Yellow'` exists only in `team_info` (the *right* frame), so its row is tagged `right_only`; `'Green'` exists only in `df` (the *left* frame), so its row is tagged `left_only`. B swaps the two — a common mix-up of which side "left" and "right" refer to (they're the *first* and *second* arguments to `.merge()`, i.e. `df` and `team_info` respectively, not related to alphabetical or physical print order). C is wrong — `both` is reserved for keys present in *both* frames (like `Red` or `Blue`), which neither `Yellow` nor `Green` is. D is wrong — `indicator=True` works with any `how=` value, including `'outer'`; that's actually one of the most common combinations, used specifically to audit which rows didn't match.
5. **B** — `df` has no column named `manager` (only `team_info` does), so `df.merge(team_info, on='manager')` raises `KeyError: 'manager'` — a merge key passed to `on=` must exist in *both* frames. A is valid — this is exactly Q3's correct row-wise stack. C is valid — `.join()`'s `on=` parameter is built for exactly this: it matches a *column* on the caller (`df['team']`) against the *index* of the other frame (`team_info.set_index('team')`), which is the correct fix for Q2's bug. D is valid syntax — `pd.concat([...], axis=1)` doesn't validate or require matching columns; it just glues frames side by side by index (even producing duplicate `team` columns here), which is messy but not an error.
