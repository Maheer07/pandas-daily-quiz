## Q1. Building on Day 21's `.str` lesson and Day 22's `.dt` lesson, using the recurring `df6` with its `joined` column, what does this print? (Roadmap #17, #18)

```python
import pandas as pd
data6 = {'name': ['Alice', 'Bob', 'Carol', 'Dave', 'Eve', 'Frank'],
         'team': ['Red', 'Blue', 'Red', 'Blue', 'Red', 'Blue'],
         'region': ['North', 'South', 'North', 'North', 'South', 'South'],
         'joined': ['2023-01-10', '2023-02-15', '2023-01-10', '2023-03-20', '2023-02-15', '2023-03-20'],
         'score': [88, 45, 92, 60, 75, 50]}
df6 = pd.DataFrame(data6, index=[100, 101, 102, 103, 104, 105])

df6['joined'] = pd.to_datetime(df6['joined'])
print(df6['joined'].str.contains('01').tolist())
```
A. `[True, False, True, False, False, False]` — matches `'01'` as a literal substring of each original date string
B. Raises an `AttributeError`, because `.str.contains()` requires string-typed data, and `joined` is now `datetime64` after the `pd.to_datetime()` conversion — this needs `.dt`, not `.str`
C. Raises an `AttributeError`, but because `.dt` must always be called before `.str` can work on any column, even ones that were never converted
D. `[True, True, True, True, True, True]`, because every date in 2023 implicitly contains `'01'` somewhere in its ISO representation

## Q2. Spot the bug: this is meant to reproduce Day 23 Q1's mean-score-by-team/region table using `pd.crosstab()` instead of `pivot_table`. What actually happens? (Roadmap #19)

```python
print(pd.crosstab(df6['team'], df6['region'], values=df6['score']))
```
A. Produces the exact same mean table as `pivot_table` — `crosstab` infers `aggfunc='mean'` automatically whenever `values=` is a numeric column
B. Raises a `ValueError`: `values` was passed without `aggfunc`, and `crosstab` requires the two to be given together — unlike `pivot_table`, it has no default aggregation function
C. Produces a table of raw row counts, silently ignoring the `values=` argument entirely
D. Raises a `TypeError`, because `crosstab`'s first two positional arguments must be column name strings, not Series objects

## Q3. Building on Day 24's `.stack()`/`.melt()` lesson, do these two lines produce an identical result? (Roadmap #19, #20)

```python
piv2 = pd.pivot_table(df6, index='team', columns='region', values='score')

a = piv2.stack()
b = (piv2.reset_index()
         .melt(id_vars='team', var_name='region', value_name='score')
         .set_index(['team', 'region'])['score'])

print(a.equals(b))
```
A. `True` — both reshape the same wide table into the same long `(team, region) -> score` values, so they must be equal
B. `False` — `.stack()` walks the columns within each row first, in `(team, region)` order, while `.melt()` walks one whole value-column at a time, in `(region, team)` order; `.equals()` checks both values *and* position/order, and the two don't match here even though the underlying data is identical
C. `False`, because `.melt()` returns a `DataFrame`-shaped result while `.stack()` returns a plain `Series`, so `.equals()` always returns `False` when comparing across those two reshaping methods
D. Raises a `TypeError`, because `.equals()` can't compare two `Series` that were built via different reshaping methods

## Q4. Building on Q1's `.dt`/`.str` contrast and Day 23 Q5's "pivot columns can be built from `.dt.month`" trick, trace through this chain. What happens on the last line? (Roadmap #17, #18, #19, #20)

```python
df6['joined'] = pd.to_datetime(df6['joined'])
piv = df6.pivot_table(index='team', columns=df6['joined'].dt.month, values='score')
melted = piv.reset_index().melt(id_vars='team', var_name='month', value_name='avg_score')

print(melted['month'].str.startswith('1').tolist())
```
A. `[True, True, False, False, False, False]` — treats `month` as if it held the strings `'1'`, `'2'`, `'3'`
B. Raises an `AttributeError` — `melt`'s `var_name` column carries over the *integer* month labels that `.dt.month` produced as the pivot table's columns; nothing in this chain ever converts them to strings, so `.str` has nothing string-like to work on
C. `[False, False, False, False, False, False]`, because none of the month values start with the digit `1` once treated as strings
D. Raises a `KeyError`, because `melt`'s `var_name='month'` doesn't actually create a column called `'month'` unless `value_name` is also a string literal

## Q5. Using the recurring `df6` (`joined` already converted to `datetime64` as in Q1), which line raises an error? (Roadmap #17, #18, #19, #20)

```python
import pandas as pd
data6 = {'name': ['Alice', 'Bob', 'Carol', 'Dave', 'Eve', 'Frank'],
         'team': ['Red', 'Blue', 'Red', 'Blue', 'Red', 'Blue'],
         'region': ['North', 'South', 'North', 'North', 'South', 'South'],
         'joined': ['2023-01-10', '2023-02-15', '2023-01-10', '2023-03-20', '2023-02-15', '2023-03-20'],
         'score': [88, 45, 92, 60, 75, 50]}
df6 = pd.DataFrame(data6, index=[100, 101, 102, 103, 104, 105])
df6['joined'] = pd.to_datetime(df6['joined'])
```
A. `df6['team'].str.lower()`
B. `df6['joined'].dt.day`
C. `df6.pivot_table(index='team', columns='region', values='score').stack()`
D. `df6.pivot(index='team', columns='region', values='joined')`

## Answer key

1. **B** — `pd.to_datetime()` already converted `joined` to a real `datetime64` column before `.str.contains()` is ever called, and the `.str` accessor only works on string-typed data; calling it on a datetime-typed Series raises `AttributeError: Can only use .str accessor with string values, not datetime64`. A is the trace you'd get if `joined` were *still* the original string column (it's not — conversion already happened). C invents a backwards rule — there's no requirement that `.dt` must run first before `.str` works on unrelated string columns; the real issue here is that `joined` specifically is no longer string-typed at all. D is wrong — there's no implicit substring magic tied to "being in 2023"; nothing here even reaches the point of comparing substrings, since the accessor itself fails first.
2. **B** — unlike `pivot_table`, `pd.crosstab()` has no default `aggfunc`; its docs require `values` and `aggfunc` to be supplied together, and passing only `values` raises `ValueError: values cannot be used without an aggfunc.` A wrongly assumes `crosstab` quietly falls back to `'mean'` the way `pivot_table` does — it has no such default at all. C describes what plain `pd.crosstab(df6['team'], df6['region'])` (no `values=`) would do, not this call, which fails before producing any table. D is wrong — `crosstab`'s first two arguments accept any array-like, including a `Series`, not just column-name strings (that restriction applies to `.pivot()`/`.pivot_table()`'s `index=`/`columns=`, not `crosstab`'s positional args).
3. **B** — `.stack()` iterates each row's columns in order before moving to the next row, giving the index order `(Blue, North), (Blue, South), (Red, North), (Red, South)`. `.melt()` instead processes one whole `value_vars` column at a time across all rows, giving `(Blue, North), (Red, North), (Blue, South), (Red, South)` — the same four values, in a different order. `.equals()` requires matching values *and* matching position (it does not sort or align by label first), so it reports `False` even though both Series hold identical `(team, region) -> score` mappings. A wrongly assumes same data implies `.equals()` returns `True` regardless of order. C is wrong on the facts — after `.set_index(['team', 'region'])['score']`, `b` is also a plain `Series`, not a `DataFrame`, so that isn't the actual reason for the mismatch. D is wrong — `.equals()` works perfectly well between any two same-shaped `Series`/`DataFrame` objects; no error is raised, it just returns a boolean.
4. **B** — `df6['joined'].dt.month` returns integers, and passing that Series as `columns=` in `pivot_table` makes those same integers (`1`, `2`, `3`) the pivot table's column labels. `.melt()`'s `var_name='month'` simply carries those former column labels into the new `month` column verbatim — nothing in this chain ever stringifies them — so `melted['month']` holds integer-like values, and `.str.startswith('1')` raises `AttributeError: Can only use .str accessor with string values, not integer`. A assumes the values were coerced to text at some point, which never happens. C makes the same mistaken assumption as A but with the opposite (also wrong) boolean results. D is wrong — `melt(var_name='month')` does exactly what its name says: it creates a column literally named `'month'`, no extra condition on `value_name` required.
5. **D** — `.pivot()` performs no aggregation and requires at most one row per index/columns combination; `df6` has two rows for `Red`/`North` (Alice and Carol), so `.pivot(index='team', columns='region', values='joined')` raises `ValueError: Index contains duplicate entries, cannot reshape` — the same duplicate-key failure as Day 23 Q3, just with a datetime-typed `values=` column instead of a numeric one (the dtype of `values` is irrelevant to this error; only the duplicate index/column pairing matters). A is valid — `team` holds strings, so `.str.lower()` runs fine. B is valid — `joined` is genuinely `datetime64` here (converted above `df6`'s creation), so `.dt.day` works. C is valid — `pivot_table` aggregates the `Red`/`North` duplicates into a mean automatically, and `.stack()` then reshapes that single-level-column result into a `Series` without issue.
