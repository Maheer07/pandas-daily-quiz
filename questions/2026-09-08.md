## Q5. What does the following print?

```python
import numpy as np
arr = np.array([100, 200, 300, 400, 500])
idx = np.array([0, -1, 2])
print(arr[idx])
```
A. [100 500 300]
B. [100 400 300]
C. [100 500]
D. Raises an IndexError

## Answer key

1. **A** — `-3` maps to index 2 (`30`) and `-1` maps to index 4 (`50`), but slice stops are exclusive, so the slice takes indices 2-3 only: `[30, 40]`. B wrongly includes the element at the stop index (forgetting slices exclude the stop). C shifts the start one position later, as if `-3` meant index 3. D shifts the whole window one position earlier.
2. **A** — `arr[1, -1]` selects row 1 (`[4, 5, 6]`) and its last element via `-1`, giving `6`. B is what you'd get from `-2` (second-to-last), not `-1`. C comes from indexing row 0 instead of row 1. D confuses `arr[1, -1]` (a single scalar) with `arr[1]` (the whole row).
3. **A** — Assigning a float into an `int`-dtype array truncates toward zero silently (no rounding, no error), so `25.7` becomes `25`, giving `[10, 25, 30]`. B wrongly assumes NumPy rounds to the nearest integer instead of truncating. C wrongly assumes the assignment has no effect. D wrongly assumes an incompatible-type error is raised — the cast happens silently instead.
4. **A** — The same truncation-toward-zero rule applies to negatives: NumPy chops the fractional part rather than flooring, so `-3.7` becomes `-3`, not `-4`. B is what you'd get with `floor()` instead of truncation — a common mix-up. C forgets the array is `int32`, which can't hold a fractional value. D wrongly assumes an error is raised; the cast is silent.
5. **A** — Fancy indexing with an integer array gathers elements independently by position, and negative indices resolve exactly as they do in basic indexing: `arr[0]=100`, `arr[-1]=500`, `arr[2]=300`, giving `[100, 500, 300]`. B miscomputes `-1` as if it were index 3 (`400`) instead of index 4 (`500`). C wrongly assumes a negative index shrinks the result. D wrongly assumes fancy indexing rejects negative indices, but they work fine.
