A. `[True, False, True, True]`

## Q2. Building on Day 19's `apply`/`map` lesson (prefer a vectorized op over calling a function per row), the same `df` gets a combined tag column. Spot the bug: this is meant to split `tag` back into two new columns, but doesn't do what's intended. What actually happens? (Roadmap #17)

```python
df['tag'] = df['name'] + '_' + df['team']
df[['first', 'second']] = df['tag'].str.split('_')
```
A. Works fine — `first` ends up holding each `name` and `second` each `team`, exactly like splitting a column in two
B. Raises a `ValueError`, because `.str.split()` without `expand=True` returns a Series of two-item lists, not a two-column result, so assigning it to `df[['first', 'second']]` doesn't broadcast correctly
C. Raises an `AttributeError`, because `.str.split()` can only be called with `expand=True` — calling it with just a delimiter is invalid
D. Works fine, but both `first` and `second` end up holding the full `['name', 'team']` list for every row

## Q5. Building on Day 20's `df6` (`name`, `team`, `region`, `score` columns, `score` numeric), which line raises an error? (Roadmap #17)

```python
data6 = {'name': ['Alice', 'Bob', 'Carol', 'Dave', 'Eve', 'Frank'],
         'team': ['Red', 'Blue', 'Red', 'Blue', 'Red', 'Blue'],
         'region': ['North', 'South', 'North', 'North', 'South', 'South'],
         'score': [88, 45, 92, 60, 75, 50]}
df6 = pd.DataFrame(data6, index=[100, 101, 102, 103, 104, 105])
```
A. `df6['region'].str.upper()`
B. `df6['score'].str.upper()`
C. `df6['team'].str.contains('ed')`
D. `df6['name'].str.split(' ')`

## Answer key

1. **A** — `case=False` makes `.str.contains()` match case-insensitively, so it compares the *letter* `'a'` regardless of case. `'Alice'` contains an uppercase `'A'`, which matches `'a'` case-insensitively, so it's `True` (not `False`) — along with `'Carol'` and `'Dave'`, which both contain a lowercase `'a'`. Only `'Bob'` has no `'a'` at all, giving `[True, False, True, True]`. B wrongly assumes `'Alice'` doesn't count because its only `'a'`-like letter is capitalized — that's exactly what `case=False` is for. C is wrong — `case` takes a boolean, not a string; passing `False` is correct usage. D is wrong — `'Bob'` genuinely has no `a`/`A` anywhere in it, so it can't be `True`.
2. **B** — `.str.split('_')` without `expand=True` returns a **Series whose elements are lists** like `['Alice', 'Red']`, not a two-column table. Assigning a 1-D Series of lists to `df[['first', 'second']]` (two columns) doesn't line up shape-wise, and pandas raises `ValueError: Columns must be same length as key`. A describes the result you'd get *with* `expand=True` (see Q3), not this code. C is wrong — `.str.split('_')` is perfectly valid without `expand=True`; it just returns a different (list-valued) shape than you might want. D is wrong — there's no behavior where every row collapses to the same shared list; each row's list is still its own `[name, team]` pair, it's just the *assignment* to two columns that fails.
3. **A** — passing `expand=True` tells `.str.split()` to return an actual multi-column DataFrame (one column per split piece) instead of a Series of lists, so it assigns cleanly into `df[['first', 'second']]`. B is wrong — it drops the `.str` accessor entirely; `Series` has no `.split()` method of its own, so this raises `AttributeError: 'Series' object has no attribute 'split'`. C is wrong — unpacking `df['tag'].str.split('_')` (a length-4 Series, one list per row) into exactly two variables tries to unpack 4 items into 2 names, raising `ValueError: too many values to unpack`. D is wrong — `expand=False` is the default and behaves identically to Q2's buggy original line, still returning a Series of lists and still raising the same `ValueError`.
4. **A** — `len()` on a `Series` (like `len()` on any pandas object) returns its **length** — the number of rows, `4` — regardless of what the values look like. `.str.len()`, by contrast, is the vectorized *string*-length operation, applied per element: `'Alice'`→5, `'Bob'`→3, `'Carol'`→5, `'Dave'`→4. B just swaps the two outputs' order. C wrongly assumes `.str.len()` also returns the row count instead of per-element lengths. D is wrong — `len()` works on a `Series` exactly like it works on a list or array, no error.
5. **B** — `df6['score']` is a numeric (`int64`) column, and the `.str` accessor only works on string-typed data; calling `.str.upper()` on it raises `AttributeError: Can only use .str accessor with string values`. A is valid — `region` holds strings, so `.str.upper()` works fine. C is valid — `team` holds strings, so `.str.contains('ed')` runs fine (matching `'Red'`). D is valid — `name` holds strings, so `.str.split(' ')` runs fine (even though none of these names contain a space, it just returns one-item lists, not an error).
