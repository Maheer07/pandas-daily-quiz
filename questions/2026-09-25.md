## Q1. Combining Day 11's boolean filtering with Day 14's sorting, what does this print? (Roadmap #9, #12)

```python
import pandas as pd
data = {'name': ['Alice', 'Bob', 'Carol', 'Dave'], 'age': [25, 30, 35, 40], 'score': [88, 45, 92, 60]}
df = pd.DataFrame(data, index=[100, 101, 102, 103])
result = df[(df['age'] >= 30) & (df['score'] >= 60)].sort_values('score', ascending=False)
print(result['name'].tolist())
```
A. `['Carol', 'Dave']`
B. `['Dave', 'Carol']`
C. `['Carol', 'Alice', 'Dave', 'Bob']`
D. Raises a `ValueError`, because you can't call `.sort_values()` directly on the result of a boolean filter without first reassigning it to a variable

## Q3. Spot the bug: building on Day 12's `assign` and Day 13's `fillna`, this is meant to add a `total` column with no gaps, but doesn't do what's intended. What does it actually print? (Roadmap #10, #11)

```python

import numpy as np
data = {'name': ['Alice', 'Bob', 'Carol', 'Dave'],
        'age': [25, 30, 35, 40],
        'score': [88, 45, 92, 60],
        'bonus': [5, 10, np.nan, 20]}
df = pd.DataFrame(data, index=[100, 101, 102, 103])

df['bonus'].fillna(0)
df2 = df.assign(total=df['score'] + df['bonus'])

```

C. `[93.0, 55.0, nan, 80.0]`

## Q4. Combining Day 9's `.loc` column selection with Day 14's `sort_index`, what does this print? (Roadmap #9, #12)

```python
import pandas as pd
data = {'name': ['Alice', 'Bob', 'Carol', 'Dave'], 'age': [25, 30, 35, 40], 'score': [88, 45, 92, 60]}
df = pd.DataFrame(data, index=[100, 101, 102, 103])
filtered = df.loc[df['score'] > 50, ['name', 'age']]
print(filtered.sort_index(ascending=False).columns.tolist(), filtered.index.tolist())
```

## Q5. Given the `bonus`-augmented `df` from Q2/Q3, which line raises an error? (Roadmap #9, #10, #11, #12)

A. `df.dropna(subset=['bonus']).sort_values('score', ascending=False)`
B. `df.loc[df['score'] > 60].sort_index(by='name')`
C. `df.drop(df[df['age'] < 28].index)`
D. `df[(df['age'] > 25) & (df['bonus'].notna())]`

## Answer key

1. **A** — `(df['age'] >= 30) & (df['score'] >= 60)` is `True` only for Carol (35, 92) and Dave (40, 60); Bob fails on score (`45 < 60`) and Alice fails on age (`25 < 30`). Sorting the 2-row result by `score` descending keeps Carol (92) ahead of Dave (60): `['Carol', 'Dave']`. B is the ascending-sort mistake — sorting the same two rows the other direction. C ignores the filter entirely and sorts all four original rows by score descending, as if the boolean mask had no effect. D is wrong — chaining `.sort_values()` straight onto a boolean-filtered DataFrame is completely normal; no reassignment is required first.
2. **B** — `dropna(subset=['bonus'])` checks only the `bonus` column for NaNs and drops just the row(s) where it's missing (Carol, index 102), while every column — including `bonus` itself — stays in the result. A removes the entire `bonus` column, which answers "drop the column" rather than "drop the row." C is the classic `axis=0` vs `axis=1` mix-up — `dropna(axis=1)` drops whole *columns* with any NaN, so it would remove `bonus` entirely rather than the one bad row. D doesn't drop anything at all; it fills every NaN in `df` with `0`.
3. **C** — `df['bonus'].fillna(0)` returns a new Series that's never reassigned and `inplace=True` was never passed, so `df['bonus']` still has its original NaN for Carol. `assign` then computes `df['score'] + df['bonus']` using that still-NaN `bonus`, so Carol's `total` is `92 + nan = nan`, giving `[93.0, 55.0, nan, 80.0]`. A wrongly assumes the earlier `fillna(0)` call mutated `df['bonus']` in place, making Carol's total just her score. B additionally assumes NaN quietly becomes `0` in an int-like column and drops the `.0` decimals, neither of which happens (adding NaN propagates NaN, and the column stays float). D is wrong — `assign` (like normal arithmetic) doesn't error on NaN; it just propagates it into the result.
4. **D** — `.loc[boolean_mask, column_list]` filters rows where `score > 50` (Alice 88, Carol 92, Dave 60 — Bob's 45 fails) and keeps only `['name', 'age']`, giving `filtered` with index `[100, 102, 103]`. `sort_index(ascending=False)` returns a **new**, reordered object without modifying `filtered` in place, and `sort_index` only reorders rows (not columns) unless you also pass `axis=1` — so `filtered.index` is still `[100, 102, 103]` and the column list is unaffected: `(['name', 'age'], [100, 102, 103])`. A wrongly assumes `sort_index()`'s result overwrote `filtered` itself. B wrongly assumes `sort_index(ascending=False)` also alphabetizes the columns. C is wrong — combining a boolean row selector with a list of column labels in `.loc[...]` is exactly the standard, documented usage from Day 9.
5. **B** — `sort_index()` has no `by` parameter at all — that keyword belongs to `sort_values()` only — so `df.loc[df['score'] > 60].sort_index(by='name')` raises `TypeError: sort_index() got an unexpected keyword argument 'by'`. A is valid — chaining `dropna(subset=...)` into `sort_values()` is a normal pipeline. C is valid — `.drop()` happily accepts an `Index` object (here, the labels where `age < 28`) as its `labels` argument. D is valid — `&` combining two boolean masks, one of them built from `.notna()`, is exactly the documented way to combine conditions.
