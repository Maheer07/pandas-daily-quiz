## Q2. Spot the bug: this is meant to print the average score per team, but doesn't do what's intended. What actually happens? (Roadmap #13)

```python
import pandas as pd
data = {'name': ['Alice', 'Bob', 'Carol', 'Dave'],
        'team': ['Red', 'Blue', 'Red', 'Blue'],
        'age': [25, 30, 35, 40],
        'score': [88, 45, 92, 60]}
df = pd.DataFrame(data, index=[100, 101, 102, 103])
avg_scores = df.groupby('team').mean()['score']
print(avg_scores)
```
A. Raises a `TypeError`, because `.mean()` is called on the whole grouped DataFrame (including the string `name` column) before `['score']` narrows it down, and pandas can't average text
B.
```
team
Blue    52.5
Red     90.0
Name: score, dtype: float64
```
C. Pandas silently skips the non-numeric `name` column and prints the same correct averages as B
D. Prints an average of the `name` strings alongside the numeric averages, since `groupby().mean()` coerces all columns

## Q3. Which line correctly computes both the average *and* the maximum score per team, in a single result? (Roadmap #13)

## Q4. Which line produces a **DataFrame** (not a Series) holding the average score per team, with `team` as a normal column rather than the index? (Roadmap #13)

## Q5. Given the same `team`-augmented `df`, which line raises an error? (Roadmap #13)

A. `df.groupby('team')['score'].agg(['mean', 'max'])`
B. `df.groupby(['team', 'age'])['score'].sum()`
C. `df.groupby('team')['bonus'].mean()`
D. `df.groupby('team')['score'].agg('sum')`

## Answer key

1. **A** — Selecting `['score']` *before* calling `.mean()` narrows the grouped object to just the numeric `score` column, so the average is computed cleanly. By default `groupby` also **sorts groups alphabetically by key** (`Blue` before `Red`), not by order of first appearance, giving `Blue 52.5, Red 90.0`. B is the tempting-but-wrong "order of appearance" answer (Red appears first in the data, but that's not how `sort=True`, the default, orders groups). C mixes up `.sum()` with `.mean()` — that's the total score per team, not the average. D is wrong — selecting a single column with `['score']` before aggregating works fine without `numeric_only`; that argument only matters when you aggregate *all* columns at once (see Q2).
2. **A** — `.mean()` is called on the *entire* grouped object first, before `['score']` ever narrows it down — so pandas tries to average every column, including the string `name` column, and raises `TypeError: dtype 'str' does not support operation 'mean'`. The fix is to select the column first (`df.groupby('team')['score'].mean()`, as in Q1) or pass `numeric_only=True`. B is the result you'd get *if* the column were selected first — that's not what this code does. C is wrong — current pandas no longer silently drops non-numeric columns from aggregations like `.mean()`; it raises instead of guessing what you meant. D is wrong — pandas never tries to "average" strings; it errors rather than producing nonsense.
3. **A** — `df.groupby('team')['score'].agg(['mean', 'max'])` narrows to the numeric `score` column first, then applies both functions, giving a two-column DataFrame (`mean`, `max`) indexed by `team`. B looks similar but applies `.agg(['mean', 'max'])` to the *whole* grouped DataFrame before selecting `'score'` — exactly Q2's trap — so it hits the string `name` column and raises `TypeError` before the column selection ever happens. C chains `.mean()` then `.max()` sequentially, which collapses everything down to one overall scalar (the higher of the two team means, `90.0`), not a per-team breakdown of two stats. D is invalid column-selection syntax — `df[...]` with a bare comma-separated tuple like `'score', 'mean', 'max'` isn't accepted for multi-item selection (pandas requires a list, e.g. `[...]`), so it raises a `ValueError`.
4. **A** — `as_index=False` tells `groupby` to keep the group key as a regular column instead of moving it into the index, so `.mean()` returns a DataFrame with both a `team` column and a `score` column. B is the default behavior (`as_index=True`), which returns a **Series** indexed by `team`, not a DataFrame. C looks like it might "restore" `team` as a column, but `reset_index(drop=True)` explicitly *discards* the old index instead of turning it into a column — so `team` disappears entirely, leaving only a Series of scores with a fresh `0, 1` index. D still uses the default `as_index=True` (and computes the wrong statistic besides), so it's a Series indexed by `team`, not a DataFrame with `team` as a column.
5. **C** — `df` in this question never had a `bonus` column defined (that was from earlier days' DataFrame), so selecting `df.groupby('team')['bonus']` raises `KeyError: 'Column not found: bonus'`. A is valid — this is exactly Q3's correct answer. B is valid — grouping by multiple keys (`['team', 'age']`) is standard, documented `groupby` usage and produces a MultiIndex result. D is valid — passing an aggregation function as a string (`'sum'`) to `.agg()` on an already-selected numeric column works fine.
