## Q1. Extending yesterday's `team`-grouped DataFrame with a new `region` column, what does this print?

```python
import pandas as pd
data = {'name': ['Alice', 'Bob', 'Carol', 'Dave', 'Eve', 'Frank'],
        'team': ['Red', 'Blue', 'Red', 'Blue', 'Red', 'Blue'],
        'region': ['North', 'South', 'North', 'North', 'South', 'South'],
        'age': [25, 30, 35, 40, 28, 33],
        'score': [88, 45, 92, 60, 75, 50]}
df = pd.DataFrame(data, index=[100, 101, 102, 103, 104, 105])
print(df.groupby(['team', 'region'])['score'].mean())
```


## Q2. Spot the bug: this is meant to print the average and max score per team-region combo, but doesn't do what's intended. What actually happens?

```python
import pandas as pd
data = {'name': ['Alice', 'Bob', 'Carol', 'Dave', 'Eve', 'Frank'],
        'team': ['Red', 'Blue', 'Red', 'Blue', 'Red', 'Blue'],
        'region': ['North', 'South', 'North', 'North', 'South', 'South'],
        'age': [25, 30, 35, 40, 28, 33],
        'score': [88, 45, 92, 60, 75, 50]}
df = pd.DataFrame(data, index=[100, 101, 102, 103, 104, 105])
result = df.groupby(['team', 'region']).agg(['mean', 'max'])['score']
print(result)
```
A. Raises a `TypeError`, because `.agg(['mean', 'max'])` runs on the *entire* grouped DataFrame — including the string `name` column — before `['score']` ever narrows it down, and pandas can't compute a mean of strings
B.
```
             mean  max
team  region
Blue  North   60.0   60
      South   47.5   50
Red   North   90.0   92
      South   75.0   75
```
C. Pandas silently skips the non-numeric `name` column and prints the same table as B
D. Prints the mean and max of `age` alongside `score`, since `.agg()` applied before any column selection aggregates every numeric column at once

## Q3. Which line correctly computes the average `score` **and** the maximum `age` per team-region group, using a single `.agg()` call with a different aggregation per column? (Roadmap #14)

A. `df.groupby(['team', 'region']).agg({'score': 'mean', 'age': 'max'})`
B. `df.groupby(['team', 'region'])[['score', 'age']].agg(['mean', 'max'])`
C. `df.groupby(['team', 'region']).mean()[['score', 'age']]`
D. `df.groupby(['team', 'region']).agg({'score': 'mean', 'age': 'max'}).mean()`

## Q4. Which line produces a **DataFrame** with `team` **and** `region` both kept as normal columns (not part of the index)?

A. `df.groupby(['team', 'region'], as_index=False)['score'].mean()`
B. `df.groupby(['team', 'region'])['score'].mean()`
C. `df.groupby(['team', 'region'])['score'].mean().reset_index(level=0)`
D. `df.groupby(['team', 'region'])['score'].mean().to_frame()`

## Q5. Given the same `region`-augmented `df`, which line raises an error?

A. `df.groupby(['team', 'region'])['score'].sum()`
B. `df.groupby(['team', 'department'])['score'].mean()`
C. `df.groupby('team').agg({'score': ['mean', 'max'], 'age': 'mean'})`
D. `df.groupby(['team', 'region'], as_index=False).size()`

## Answer key

1. **A** — Grouping by `['team', 'region']` builds a MultiIndex where **the first key in the list becomes the outer level and the second becomes the inner level**, and groups are sorted alphabetically at each level: `Blue` before `Red` (outer), and within each team, `North` before `South` (inner). Working out the means gives `Blue/North=60.0` (Dave only), `Blue/South=47.5` (Bob 45, Frank 50), `Red/North=90.0` (Alice 88, Carol 92), `Red/South=75.0` (Eve only) — exactly A. B has the *same four numbers* but swaps which key is outer vs. inner, as if you'd called `groupby(['region', 'team'])` instead — the list order in `groupby()` directly controls level order, it doesn't get re-sorted by name. C is what you'd get by grouping on `'team'` alone and never grouping by `region` at all, collapsing the two regions together per team. D is wrong — passing a list of columns to `groupby()` and then selecting a single column with `['score']` afterward is exactly the standard, documented pattern (as used correctly in Q1 itself).
2. **A** — `.agg(['mean', 'max'])` is applied to the **entire** grouped DataFrame first, before `['score']` narrows anything down — so pandas tries to compute `.mean()` on every column, including the string `name` column, and raises `TypeError: dtype 'str' does not support operation 'mean'`, exactly like Day 16's single-key version of this trap. B is the table you'd get *only if* `['score']` were selected before `.agg(...)` (i.e. `df.groupby(['team','region'])['score'].agg(['mean','max'])` — see Q3's correct pattern), which isn't what this code does. C is wrong — modern pandas doesn't quietly drop incompatible columns from an aggregation; it raises rather than guessing. D is wrong for the same reason as A: the code never gets far enough to compute anything, numeric or not, because it errors out on `name` first.
3. **A** — A dict passed to `.agg()` maps each column name to its own aggregation function, so `{'score': 'mean', 'age': 'max'}` computes exactly one stat per column without ever touching `name`, giving a clean two-column result. B computes **both** `mean` and `max` for **both** `score` and `age` (four columns total: `score` mean & max, `age` mean & max) — not "a different aggregation per column" as asked. C calls `.mean()` on the whole grouped DataFrame before any column subsetting, which hits the same string-`name` `TypeError` as Q2, and even if it didn't, it would give the mean of `age` rather than the requested max. D actually starts by computing the exact right per-group table from A, but then chains an extra `.mean()` on top, which collapses the per-team-region breakdown into a single overall pair of numbers, losing the grouping entirely.
4. **A** — `as_index=False` tells `groupby` to leave the group keys as ordinary columns instead of moving them into the index, so the result is a DataFrame with `team`, `region`, and `score` as three normal columns. B is the default (`as_index=True`): a **Series** with a `(team, region)` MultiIndex, not a DataFrame at all. C only resets `level=0` (`team`) back to a column while `region` remains part of the index — so it's a DataFrame, but only `team` is a normal column, not both. D converts the Series to a DataFrame via `.to_frame()`, but the `(team, region)` MultiIndex stays exactly as it was — neither key becomes a normal column.
5. **B** — `df` has no `department` column (only `name`, `team`, `region`, `age`, `score`), so `groupby(['team', 'department'])` raises `KeyError: 'department'`. A is valid — grouping by both keys and summing the already-numeric `score` column works fine. C is valid — a dict passed to `.agg()` can mix a list of functions for one column (`'score': ['mean', 'max']`) with a single function for another (`'age': 'mean'`); pandas handles the mixed shapes and produces MultiIndex columns. D is valid — `.size()` counts rows per group and works fine with `as_index=False`, returning a DataFrame with `team`, `region`, and a `size` column.
