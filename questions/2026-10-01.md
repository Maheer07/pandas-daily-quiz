## Q1. Building on the recurring `team`-augmented DataFrame, you add a `region` column by mapping each team name through a dictionary. What does this print? (Roadmap #16)

```python
import pandas as pd
data = {'name': ['Alice', 'Bob', 'Carol', 'Dave'],
        'team': ['Red', 'Blue', 'Red', 'Green'],
        'score': [88, 45, 92, 60]}
df = pd.DataFrame(data, index=[100, 101, 102, 103])

region_map = {'Red': 'North', 'Blue': 'South'}
df['region'] = df['team'].map(region_map)
print(df['region'].tolist())
```
A. `['North', 'South', 'North', nan]`
B. `['North', 'South', 'North', 'Green']`
C. Raises a `KeyError`, because `'Green'` is not a key in `region_map`
D. `['North', 'South', 'North', 'North']`

## Q2. Spot the bug: this is meant to add a 10%-of-score `bonus` column per row, but doesn't do what's intended. What actually happens? (Roadmap #16)

```python
import pandas as pd
data = {'name': ['Alice', 'Bob', 'Carol', 'Dave'],
        'team': ['Red', 'Blue', 'Red', 'Green'],
        'score': [88, 45, 92, 60]}
df = pd.DataFrame(data, index=[100, 101, 102, 103])

def bonus(row):
    return row['score'] * 0.1

df['bonus'] = df.apply(bonus)
print(df['bonus'])
```
A. Raises a `KeyError`, because the default `axis=0` passes each **column** (not each row) to `bonus`, and `'score'` isn't a valid index label within any single column
B. Correctly prints a bonus column: `8.8, 4.5, 9.2, 6.0`
C. Prints `NaN` for every row, because non-numeric columns can't be multiplied by `0.1`
D. Raises a `TypeError`, because `.apply()` requires an `axis` argument to be passed explicitly

## Q3. Using the same `df` as Q2, which line computes that same 10%-of-score `bonus` column **without calling `.apply()`/`.applymap()` at all**, using a vectorized operation instead? (Roadmap #16)

B. `df['bonus'] = df.apply(lambda row: row['score'] * 0.1, axis=1)`
C. `df['bonus'] = df['score'].apply(lambda x: x * 0.1)`

## Q4. Still using `df` from Q2 (unmodified — no `region` or `bonus` columns), what does this print? (Roadmap #16)

```python
def grade(s):
    return 'Pass' if s >= 60 else 'Fail'

df['result'] = df['score'].map(grade)
print(df['result'].tolist())
```
A. `['Pass', 'Fail', 'Pass', 'Pass']`
B. `['Pass', 'Fail', 'Pass', 'Fail']`
C. Raises a `TypeError`, because `.map()` only accepts a dictionary, not a function
D. `['Pass', 'Fail', 'Pass', 'Pass', 'Pass']`

## Q5. Given the original `df` from Q1 (just `name`, `team`, `score` — no `region` or `bonus` column added), which line raises an error? (Roadmap #16)

A. `df['score'].map({88: 'A', 92: 'A'})`
B. `df.apply(lambda row: row['score'] + row['bonus'], axis=1)`
C. `df['team'].apply(lambda s: s.upper())`
D. `df[['score']].apply(lambda col: col * 2)`

## Answer key

1. **A** — `Series.map()` with a dict looks up each value as a key; `'Red'` and `'Blue'` are in `region_map` and resolve to `'North'`/`'South'`, but `'Green'` has no entry, so it silently becomes `NaN` (not an error, and not left as `'Green'`). B is wrong because it confuses `.map()` with `.replace()` — `.replace()` leaves unmatched values unchanged, but a dict passed to `.map()` turns every unmatched value into `NaN`. C is wrong — `.map()` never raises for missing dict keys; it just produces `NaN`. D is wrong — there's no fallback to a "most recent" or default mapped value; missing keys always become `NaN`, never a neighboring value.
2. **A** — `DataFrame.apply()` defaults to `axis=0`, which passes each **column** (as a Series indexed by the DataFrame's row index, `100–103`) to the function — not each row. Inside `bonus`, `row['score']` tries to look up the label `'score'` in that column's index, which only ever contains `100, 101, 102, 103`, so it raises `KeyError: 'score'` on whichever column is processed. B is the result you'd get with the fix (`axis=1`, see Q3), not what this code does. C is wrong — pandas doesn't quietly turn incompatible operations into `NaN` here; it raises before producing any output. D is wrong — `axis` is an optional keyword that defaults to `0`; omitting it doesn't raise anything by itself (the `KeyError` comes from the lambda's logic, not from a missing argument).
3. **A** — `df['score'] * 0.1` multiplies the whole numeric Series elementwise in one vectorized operation, with no Python-level function call per row. B is wrong for the stated criterion — it does produce the correct numbers, but it still calls `.apply(..., axis=1)`, invoking the lambda once per row. C is wrong for the same reason — `Series.apply()` still runs the lambda element by element rather than using a vectorized op. D is wrong both ways — it still calls `.applymap()` (not a vectorized op), and `.applymap()` was deprecated in pandas 2.1 and has been **removed entirely as of pandas 3.0** in favor of `DataFrame.map()`, so on current pandas this line raises `AttributeError: 'DataFrame' object has no attribute 'applymap'` before it ever gets to multiply anything.
4. **A** — `Series.map()` happily accepts a plain function (not just a dict), calling it once per element: `88 → 'Pass'`, `45 → 'Fail'`, `92 → 'Pass'`, and `60 → 'Pass'` because the condition is `>= 60`, which includes 60 itself. B is the off-by-one mistake of treating the boundary as exclusive (`> 60`), which would wrongly mark a score of exactly 60 as `'Fail'`. C is wrong — `.map()` is overloaded to accept a dict, a function, or a Series; it's `.replace()`-style dict-only mapping that doesn't exist here. D is wrong — there are only 4 rows in `df`, so the result can't have 5 elements.
5. **B** — `df` has no `bonus` column (only `name`, `team`, `score`), so inside the `axis=1` apply, each `row` is a per-row Series indexed by column name, and `row['bonus']` raises `KeyError: 'bonus'`. A is valid — `Series.map()` with a dict just returns `NaN` for unmapped values (`45` and `60` here), exactly like Q1; it doesn't error. C is valid — `.apply()` on a Series of strings with a function that calls `.upper()` works fine, since every element really is a string. D is valid — selecting a single-column DataFrame with `df[['score']]` and applying a column-wise function (the `axis=0` default) to double a numeric column works without issue.
