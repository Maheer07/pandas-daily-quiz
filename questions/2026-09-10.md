## Q4. Spot the bug. `scores` has one row per student and one column per subject. This is meant to print each student's average score, but has a bug:

```python
import numpy as np
scores = np.array([[85, 90, 78], [92, 88, 95]])
avg_per_student = scores.mean(axis=0)
print(avg_per_student)
```
Which line correctly fixes it?

A. `scores.mean(axis=1)`
B. `scores.T.mean(axis=1)`
C. `scores.mean()`
D. `scores.sum(axis=1) / scores.shape[0]`

## Q5. Combining Day 3's boolean masking with today's aggregations, what does this print?

```python
import numpy as np
arr2d = np.array([[1, 2, 3], [4, 5, 6]])
print((arr2d > 3).sum(axis=1))
```
A. [0 3]
B. [1 1 1]
C. [[False False False] [ True  True  True]]
D. Raises a TypeError, since `sum()` can't be called on a boolean array

## Answer key

1. **A** — `axis=0` collapses *down the rows*, summing each column independently: `[1+4, 2+5, 3+6] = [5, 7, 9]`. B is the `axis=1` result (row sums), a classic axis mix-up. C is the grand total (`arr2d.sum()` with no axis), collapsing everything to a scalar. D just flattens the array without reducing anything.
2. **A** — `axis=1` collapses *across the columns* of each row, giving one value per row: `[(1+2+3)/3, (4+5+6)/3] = [2., 5.]`. B (`axis=0`) instead gives one value per column: `[2.5, 3.5, 4.5]`. C and D both collapse the entire array to a single scalar (`3.5`) — `axis=None` is the default, so C and D are actually identical to each other and neither matches the per-row shape asked for.
3. **A** — `arr2d.max(axis=0)` gives column maxima `[4, 5, 6]`; `keepdims=True` keeps that as shape `(1, 3)` instead of squeezing it to `(3,)`. Subtracting broadcasts the `(1,3)` array against every row of the `(2,3)` array: row 0 → `[1-4,2-5,3-6]=[-3,-3,-3]`, row 1 → `[4-4,5-5,6-6]=[0,0,0]`. B has the right values but forgets `keepdims=True` changes the shape to `(1,3)`, not `(3,)`. C wrongly assumes the column max is subtracted from *every* row using row 0's differences again for row 1. D is wrong because `(1,3)` and `(2,3)` broadcast together fine — the axis of size `1` is exactly the one broadcasting is allowed to stretch.
4. **A** — The buggy code uses `axis=0`, which averages *down each column* (per subject) instead of *across each row* (per student). `axis=1` fixes it, correctly giving `[(85+90+78)/3, (92+88+95)/3] = [84.33, 91.67]`. B looks like a fix but still reduces the wrong axis: `scores.T` has shape `(3,2)`, and `.mean(axis=1)` on it averages across students for each subject — still per-subject, not per-student. C collapses everything to one overall scalar. D uses the correct axis for the sum (`axis=1`, per-student totals `[253, 275]`) but divides by `scores.shape[0]` (2, the number of students) instead of `scores.shape[1]` (3, the number of subjects), giving the wrong numbers (`[126.5, 137.5]`) despite looking like a fix.
5. **A** — `arr2d > 3` produces a boolean mask `[[F,F,F],[T,T,T]]`; booleans behave as `0`/`1` under `sum()`, and `axis=1` sums each row's `True` count: row 0 has zero values `>3` → `0`; row 1 has all three `>3` → `3`, giving `[0, 3]`. B is the `axis=0` result (per-column counts: each column has exactly one `True`, from row 1), a repeat of the axis-mix-up trap. C wrongly assumes `.sum(axis=1)` does nothing and just returns the mask unchanged. D is false — NumPy booleans are a numeric-compatible dtype and aggregate perfectly fine, no error is raised.
