## Q3. Spot the bug: this is meant to reshape `df6` the same way Q1's `pivot_table` did, using the stricter `.pivot()` instead. What actually happens? (Roadmap #19)

```python
print(df6.pivot(index='team', columns='region', values='score'))
```
A. Produces the exact same mean table as Q1's `pivot_table` — `.pivot()` and `.pivot_table()` are interchangeable whenever no explicit `aggfunc` is needed
B. Raises a `ValueError`: `Index contains duplicate entries, cannot reshape` — `Red`/`North` appears twice (Alice and Carol), and `.pivot()` has no aggregation step to collapse duplicate index/column pairs into one cell
C. Silently keeps only the *first* matching row for each team/region pair (Alice's 88, dropping Carol's 92) and reshapes the rest normally
D. Raises a `KeyError`, because `'region'` isn't a valid `columns=` argument for `.pivot()` — only `.pivot_table()` accepts a column name there

## Q4. Building on Q1's pivot table, what does the bottom-right corner print here? (Roadmap #19)

```python
piv = pd.pivot_table(df6, index='team', columns='region', values='score', margins=True)
print(piv.loc['All', 'All'])
```
A. `68.333333...` — the mean of all 6 scores combined
B. `51.666667` — that's `Blue`'s row mean, not the grand total
C. `410` — that's the raw *sum* of all 6 scores, not their mean
D. Raises a `KeyError`, because `margins=True` doesn't create a row/column literally labeled `'All'` unless `margins_name='All'` is passed explicitly

## Q5. Building on Day 22's `.dt`-accessor lesson, which line correctly builds a pivot table of mean `score` by `team` (rows) and **join month** (columns), given that `df6['joined']` is still a plain string column? (Roadmap #19, #18)

A. `df6.pivot_table(index='team', columns='joined', values='score')`
B. `df6.pivot_table(index='team', columns=pd.to_datetime(df6['joined']).dt.month, values='score')`
C. `df6.pivot_table(index='team', columns=df6['joined'].dt.month, values='score')`
D. `df6.pivot_table(index='team', columns=df6['joined'].astype(int).dt.month, values='score')`

## Answer key

1. **A** — `pd.pivot_table()`'s default `aggfunc` is `'mean'`, and rows/columns are sorted alphabetically by default: `team` (`Blue`, `Red`) becomes the row index, `region` (`North`, `South`) becomes the columns, and each cell is the mean `score` for that team/region pair — `Blue`/`North` has only Dave (60.0), `Blue`/`South` has Bob & Frank (mean 47.5), `Red`/`North` has Alice & Carol (mean 90.0), `Red`/`South` has only Eve (75.0). B wrongly assumes the default `aggfunc` is `'sum'` instead of `'mean'`. C has the right numbers but swaps which variable becomes the index vs. the columns — `index='team'` means `team` is the *row* label, not `region`. D is wrong — `aggfunc` defaults to `'mean'` and is entirely optional; no error occurs.
2. **A** — `pd.crosstab()` is purpose-built for counting occurrences of each combination of two (or more) categorical columns, with no `values=`/`aggfunc=` needed at all. B computes the *mean score* per team/region, not a count. C would actually raise `ValueError` (see Q3) because `Red`/`North` has two rows and `.pivot()` can't collapse duplicates — and even if it ran, it would show scores, not counts. D sums the `score` column per group, which is a different number entirely from a row count.
3. **B** — `.pivot()` (unlike `.pivot_table()`) performs no aggregation step; it expects at most **one** row per index/columns combination. `Red`/`North` has two rows (Alice's 88 and Carol's 92), so pandas can't decide which value goes in that cell and raises `ValueError: Index contains duplicate entries, cannot reshape`. A is wrong — this is exactly the distinction between the two methods: `.pivot_table()` aggregates duplicates automatically, `.pivot()` does not. C invents a "keep the first row" fallback that `.pivot()` doesn't have — it errors instead of silently dropping data. D is wrong — `columns='region'` is valid syntax for `.pivot()` too; the failure is about duplicate *data*, not an invalid argument name.
4. **A** — with `margins=True`, pandas adds an extra `'All'` row and column holding the aggregate (here, mean) over *all* the data in that row/column, and the bottom-right `'All'`/`'All'` cell is the grand mean across every value used in the table — all 6 scores: `(88+45+92+60+75+50)/6 = 68.333...`. B is `Blue`'s row-level mean (`(60+47.5+45+50-ish)`... more precisely `Blue`'s own `'All'` column value, `51.666667`), not the grand corner. C wrongly swaps mean for sum — `margins=True` respects whatever `aggfunc` the table already uses (`'mean'` here), it doesn't switch to summing. D is wrong — `margins_name='All'` is itself the *default*, so the row/column are labeled `'All'` automatically; no extra argument is required.
5. **B** — `pivot_table()`'s `columns=` parameter accepts any array-like, not just a column *name* string, so wrapping the conversion inline — `pd.to_datetime(df6['joined']).dt.month` — produces a Series of month integers on the fly and groups by that, without ever mutating `df6` itself. A groups by the raw date *strings* verbatim (e.g. `'2023-01-10'`), which splits rows by exact join date rather than by month — not what's intended. C fails exactly like Day 22's lesson: `df6['joined']` is still plain string-typed (no `pd.to_datetime()` was applied to *that* expression), so `.dt.month` raises `AttributeError: Can only use .dt accessor with datetimelike values`. D is wrong for a different reason — `.astype(int)` on a date string like `'2023-01-10'` isn't a valid integer literal at all, so it raises `ValueError` before `.dt.month` is ever reached.
