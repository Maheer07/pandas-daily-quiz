## Q1. Building on Day 12's name/age/score DataFrame, but now with some scores missing, what does this print?

```python
import pandas as pd
import numpy as np

data = {'name': ['Alice', 'Bob', 'Carol', 'Dave'],
        'age': [25, 30, 35, 40],
        'score': [88, np.nan, 92, np.nan]}
df = pd.DataFrame(data, index=[100, 101, 102, 103])
print(df.isna().sum())
```
A.
```
name     0
age      0
score    2
dtype: int64
```
B.
```
100    0
101    1
102    0
103    1
dtype: int64
```
C. `2` — a single scalar, since `.sum()` collapses the whole DataFrame into one number
D. Raises a `TypeError`, because you can't call `.sum()` on a boolean DataFrame

## Q2. Spot the bug: this code is meant to replace missing scores with `0`, but doesn't do what's intended. What actually happens?

```python
import pandas as pd
import numpy as np

data = {'name': ['Alice', 'Bob', 'Carol', 'Dave'],
        'age': [25, 30, 35, 40],
        'score': [88, np.nan, 92, np.nan]}
df = pd.DataFrame(data, index=[100, 101, 102, 103])

df['score'].fillna(0)
print(df['score'].tolist())
```
A. `df['score'].fillna(0)` is never reassigned and `inplace=True` was never passed, so the new filled Series is computed and immediately discarded — `df['score']` still has NaNs: `[88.0, nan, 92.0, nan]`
B. There is no bug — `fillna` operates in place by default when called directly on a column pulled from `df`, so the NaNs are filled: `[88.0, 0.0, 92.0, 0.0]`
C. Raises a `ValueError`, because `fillna` requires `inplace` to be passed explicitly, one way or the other
D. `df['score']` becomes `[88.0, 0.0, 92.0, 0.0]`, but pandas raises a `SettingWithCopyWarning` first, since `df['score']` is only a view

## Q3. Building on Day 12's `insert`, a `bonus` column (also with a gap) has been added. What does this print?

```python
import pandas as pd
import numpy as np

data = {'name': ['Alice', 'Bob', 'Carol', 'Dave'],
        'age': [25, 30, 35, 40],
        'score': [88, np.nan, 92, np.nan],
        'bonus': [5, 10, np.nan, 20]}
df = pd.DataFrame(data, index=[100, 101, 102, 103])
print(df.dropna(axis=1).columns.tolist())
```
A. `['name', 'age']` — `axis=1` drops any column containing at least one NaN; only `score` and `bonus` have missing values
B. `['name', 'age', 'score', 'bonus']` — no columns are dropped, since `dropna()` only ever removes rows, never columns
C. `[]` — every column gets dropped, since a NaN exists *somewhere* in the DataFrame
D. Raises a `ValueError`, because `axis=1` isn't a valid argument to `dropna()`

## Q4. Using the same `df` from Q3, what does this print?

```python
print(df.dropna(subset=['score']).index.tolist())
```
A. `[100, 102]` — only rows where `score` itself is NaN get dropped (Bob at 101, Dave at 103); Carol at 102 is kept even though her `bonus` is NaN
B. `[100]` — `dropna` drops any row with a NaN in *any* column, ignoring `subset`
C. `[100, 101, 102, 103]` — `subset` is ignored unless combined with `how='all'`
D. Raises a `KeyError`, because `subset` expects a single column name, not a list

## Q5. Given the same `df` (with `score` and `bonus` containing NaNs), which line raises an error?

A. `df['score'].fillna(df['score'].mean())`
B. `df.fillna({'score': 0, 'bonus': 0})`
C. `df.dropna(thresh=3)`
D. `df.isna(axis=1)`

## Answer key

1. **A** — `df.isna()` produces a same-shaped boolean DataFrame, and `.sum()` on a DataFrame sums **down each column by default** (`axis=0`), giving one count per column: `name`/`age` have none, `score` has 2 (Bob and Dave). B is the classic `axis=0` vs `axis=1` mix-up — that's what `df.isna().sum(axis=1)` would give (NaN count *per row*), not the default. C wrongly assumes `.sum()` always collapses to one grand total; on a DataFrame it sums per column unless you also chain a second `.sum()`. D is wrong — boolean DataFrames sum perfectly fine, with `True`/`False` treated as `1`/`0`.
2. **A** — `fillna()` (like `dropna`, `sort_values`, etc.) returns a **new** Series by default and leaves the original untouched unless you reassign it (`df['score'] = df['score'].fillna(0)`) or pass `inplace=True`. Here the result is thrown away, so `df['score']` is unchanged and still has NaNs. B wrongly assumes `fillna` defaults to in-place — it never does. C is wrong — `inplace` has a default (`False`); you're never required to state it. D is wrong — no warning fires here at all, because nothing is being *assigned into* a sliced/copied DataFrame; the result of `fillna` is just computed and discarded, not written anywhere.
3. **A** — `dropna(axis=1)` checks **each column** for any NaN and drops the whole column if it has one; `score` and `bonus` each contain a NaN, so only `name` and `age` survive. B wrongly assumes `dropna` can only ever target rows — `axis=1` explicitly redirects it to columns. C over-generalizes "a NaN exists somewhere" to "drop everything," but `dropna(axis=1)` evaluates columns independently, not the whole frame at once. D is wrong — `axis=1` is a fully supported, documented value for `dropna()`.
4. **A** — `subset=['score']` restricts the NaN-check to just the `score` column, so only rows where `score` itself is missing get dropped — Bob (101) and Dave (103) — while Carol (102) survives despite her `bonus` being NaN, since `bonus` isn't in the subset. B ignores `subset` entirely and applies the default any-column behavior instead. C assumes `subset` alone does nothing, which contradicts its documented purpose. D is wrong — `subset` accepts a list of column names, which is in fact the typical way to use it.
5. **D** — `isna()` takes **no positional arguments and no `axis` parameter at all** (unlike `sum()` or `dropna()`) — it always returns an elementwise boolean mask over the whole object, so passing `axis=1` raises `TypeError: isna() got an unexpected keyword argument 'axis'`. A is valid — `fillna` happily accepts a computed scalar like a column mean. B is valid — `fillna` accepts a dict mapping column names to per-column fill values. C is valid — `thresh=3` is a legitimate `dropna` argument meaning "keep rows with at least 3 non-NaN values."
